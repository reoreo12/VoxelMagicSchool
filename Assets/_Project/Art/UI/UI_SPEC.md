# UI 지침 (복셀 마법 학교) — Claude Code용 SPEC

> 마지막 갱신: 2026-11-19
> 범위: **UI 관련 내용만** 다룬다. 게임 규칙(시간, 경비원 판정, 점수 계산 규칙, 의뢰 규칙 등)은 다른 문서에서 다룬다.
> 대상: Unity 프로젝트 `Voxel_Magical_Game` / 에셋 폴더 `Assets/UI`
> 대상 세계관: 복셀 한국 마법 학교 (폴더명, 방과후→밤 구조 기준으로 추정. 다른 게임용이면 알려 주세요)

> **[잠정] 항목은 사용자 확인 전의 제안이다. Claude Code는 [미정]과 [잠정]을 임의로 확정해서 구현하지 말고, 설계 단계에서 사용자에게 확인한다.**

### 1-1. 한글 폰트 (갈무리11 / 스타더스트 3.0 비교)

- **[확정]** 한글 픽셀 폰트는 **갈무리11 TTF**와 **스타더스트 3.0 TTF** 두 가지를 프로젝트에 넣고, 추후 UI 에디터 씬에서 **직접 비교한 뒤 하나로 정한다.** (Sprout Lands 팩 폰트 `pixelFont-7-8x14-sproutLands.ttf`는 한글 지원 미확인이라 한글에는 쓰지 않는 쪽으로 간다.)
- **[미정]** 최종 폰트 선택, 사용할 크기(대사·의뢰 텍스트 11~14px, HUD 작은 글씨 9px 정도를 Claude가 예상했으나 미확정).
- **[확정]** 파일 형식은 TTF. WOFF/WOFF2나 비트맵 폰트는 쓰지 않는다.

**Claude Code 작업 지침 (TextMeshPro 폰트 에셋 제작)** **[잠정]**

TTF는 Unity가 폰트로 임포트하지만, TMP는 이를 기반으로 만든 별도의 폰트 에셋(아틀라스 텍스처 + 머티리얼)을 쓴다. 폰트 에셋 제작은 Font Asset Creator 창 대신 `execute_code` 또는 에디터 스크립트로 `TMP_FontAsset.CreateFontAsset` 등을 호출해 만든다(가능 여부는 연결된 Unity MCP에서 직접 확인).

- Render Mode: **RASTER**(또는 RASTER_HINTED). SDF는 도트 가장자리가 흐려지므로 쓰지 않는다.
- Sampling Point Size: **폰트의 설계 크기**에 맞춘다(갈무리11이면 11. 스타더스트는 설계 크기 확인 필요).
- 씬에서 쓰는 글자 크기는 설계 크기의 **정수 배**(예: 11, 22, 33)만 쓴다.
- 아틀라스 텍스처 Filter Mode: **Point**.
- Atlas Population Mode: **개발 중에는 Dynamic + Multi Atlas Textures**로 시작한다(한글 완성형 11,172자를 미리 굽는 Static은 아틀라스가 매우 커진다). **출시 전에는 게임에 실제로 나오는 글자만 모은 Static 아틀라스로 굽는다**(4-A-5, 런타임 끊김 방지).
- Dynamic 폰트 에셋은 에디터에서 글자가 추가되며 에셋이 계속 바뀐다. 출시 빌드 방식에 따라 **Clear Dynamic Data On Build** 사용 여부를 정한다. 켜면 빌드된 게임에서 글자가 처음 나올 때마다 래스터라이즈되어 끊길 수 있으니, 켠다면 시작 시 프리워밍(4-A-5)이 필요하다.
- 폰트마다 폰트 에셋을 따로 만든다(갈무리11용, 스타더스트3.0용).
- 만든 뒤 한글 문장(예: 대사 한 줄, 의뢰 제목 한 줄, 숫자)을 넣은 테스트 텍스트를 씬에 띄워 스크린샷으로 도트가 깨지지 않는지 확인한다.
- Canvas는 Pixel Perfect를 켜고 정수 배율 규칙(2장)을 지킨다.

**비교 화면 요구사항 (UI 에디터 씬)** **[잠정]**

- 같은 문장을 두 폰트로, 같은 크기(9·11·14 등)와 배경(크림색 종이, 갈색 패널, 어두운 배경)에서 나란히 보여 준다.
- 비교용 문장 예: 대사 한 줄, 의뢰 제목 + 진행 상황 한 줄(10장 항목 형식), 숫자·기호가 섞인 문장(`D-3`, `2/5`).
- 정수 배율(1×·2×·3×)과 Pixel Perfect 켠 상태에서 확인한다.
- 판단 기준(Claude 제안): 한글 글자 가독성(작은 크기에서), 글자 폭의 균일함, 자간·행간의 편안함, 영문·숫자 모양, 책 UI·종이 패널 톤과의 어울림, 라이선스.

## 2. 화면·해상도

- **[확정]** 화면 크기와 종횡비가 달라져도 UI가 잘 적응해야 한다. 스타듀밸리처럼 전체화면이나 정수 배율에서도 그래픽과 비율에 문제가 없어야 한다.
- **[확정]** 월드는 복셀 3D이고, 일부 맵은 2D 스프라이트를 3D 월드에 겹겹이 세워 배경을 겹치는 방식이다.
- **[확정]** UI는 앵커 기준으로 배치하고, 에디터에서 종횡비(16:9, 16:10, 21:9, 4:3) 프리뷰를 전환해 볼 수 있어야 한다.
- **[잠정]** 월드와 UI의 스케일을 따로 다룬다. UI는 스크린 스페이스 오버레이로 두고, 배율은 `화면 높이 ÷ 기준 높이`의 내림(정수)으로 정한다.
- **[잠정]** 기준 해상도 640×360, 타일 단위 16px, Canvas Scaler의 Reference Pixels Per Unit = 16. (Claude의 제안이고 사용자 명시 확정은 아님.)
- **[미정]** 월드 카메라가 원근인지 직교인지. 원근이면 겹겹이 세운 스프라이트 레이어마다 도트 밀도가 달라진다. UI 자체는 영향이 없다.

## 3. UI 에디터 씬

사용자가 정리한 기능 목록. 모두 **[확정]**.

- UI 크기·비율 조정
- UI 타일 구성
- 버튼·토글·슬라이더·드롭다운 등 기능별 기본 UI 프리셋 고정
- 텍스트 폰트 종류·크기·위치(주변 여백)·정렬(왼쪽/가운데/오른쪽)
- 대사 Typewriter 값(재생 속도, 흔들림 등)
- 위 요소들을 조합해 프리팹으로 구워내는 용도
- **[확정]** 아이템 아이콘 회전 방식 비교 화면(7-3 참조). 비교 결과에 따라 변환 도구로 남기거나 제거한다.
- **[확정]** 한글 폰트 비교 화면(1-1 참조). 결과가 정해지면 제거하거나 폰트 미리보기 용도로 남긴다.

Claude의 권고(**[잠정]**, 사용자 확인 전):

- 직접 만들 가치가 큰 것은 테마 에셋 한 개로 모든 위젯의 스프라이트·폰트·여백을 일괄 관리하는 기능과 해상도별 미리보기다. 나머지는 Unity 프리팹 모드·인스펙터·ScriptableObject 커스텀 에디터를 활용한다.
- 패널은 9-slice(4장)를 쓰므로 PNG로 굽지 않는다. 타일 격자 기반 장식 프레임이 필요해질 때만 에디터에서 한 장의 스프라이트로 구워 쓴다.
- **[미정]** 에디터 씬이 개발 전용인지, 빌드에 포함해 플레이어도 쓰게 할지.

## 4. 패널 9-slice 규칙

- **[확정]** 패널은 모서리를 그대로 두고 테두리와 내부만 늘리는 9-slice 방식으로 쓴다.
- 사용자 제공 16×16 주황 패널의 경계값은 L5 / T6 / R5 / B6이다. 늘어나는 중앙 영역은 같은 색 픽셀만 있어 늘려도 깨지지 않는다.
- Unity 임포트 공통 **[확정]**: Filter Mode Point, Compression None, Mesh Type Full Rect, PPU 16, Image Type Sliced. (예외: 찢어진 종이 패널은 Image Type Tiled, 10-7 참조.)
- **[잠정]** 도트 품질 설정: 크기와 위치는 정수 픽셀로 맞춘다(홀수 폭 + 중심 피벗은 0.5px 어긋남). Canvas의 Pixel Perfect를 켜고, 스프라이트 PPU와 Canvas Reference PPU를 같은 값(16)으로 맞춘다.
- **[잠정]** 성능: 9-slice Image는 사각형 최대 9개짜리 메쉬라 문제없다. 모든 UI 스프라이트를 Sprite Atlas 하나로 묶고, 매 프레임 바뀌는 UI(화살표 회전 등)와 정적 UI는 캔버스를 분리한다. 크기를 매 프레임 바꾸지 않는다.
- **[잠정]** 구현 방식: 에디터 도구가 구성(크기·여백·스프라이트·슬롯 개수)을 프리팹으로 저장하고, 게임에서는 프리팹을 배치한다. 슬롯 개수나 아이콘처럼 가변적인 값만 런타임에 데이터(ScriptableObject/JSON)로 채운다. 런타임에 PNG를 굽거나 크기별 PNG를 만들지 않는다.

## 4-A. 공통 아키텍처와 성능 규칙

화면별 명세(5장 이후)보다 먼저 지켜야 하는 공통 규칙이다. 사용자가 "확장성과 성능을 고려한 지침이어야 한다"고 요청해 추가했다. 아래는 모두 Claude의 제안이므로 기본 **[잠정]**이고, 설계 단계에서 Claude Code가 사용자에게 확인한다.

### 4-A-1. UI 기술 선택

- **[잠정]** UI는 **uGUI(Canvas + TextMeshPro)** 로 만든다. UI Toolkit은 쓰지 않는다. (이 문서의 9-slice, Tiled, Sprite Swap, Pixel Perfect, 캔버스 분리 규칙이 모두 uGUI 기준이다. **사용자 확인 필요.**)

### 4-A-2. UI 화면 스택 (열기·닫기·ESC·시간 정지 공통 처리)

책, 확장 인벤토리, 자세히 패널, 의뢰 게시판 패널, 확인 창은 모두 "열면 시간이 멈추고 ESC로 닫힌다"는 같은 동작을 가진다. 화면마다 따로 구현하지 않고 **하나의 UI 화면 관리자**가 처리한다.

- **[잠정]** 모든 팝업형 UI는 공통 인터페이스(예: `IUiScreen`: 열기, 닫기, ESC 처리 여부, 시간 정지 여부)를 구현하고, 관리자의 **스택**에 쌓는다.
- **[잠정]** **ESC는 관리자가 받아서 스택 맨 위 화면부터 닫는다.** 스택이 비어 있고 대사창도 없을 때만 책(메뉴 탭)을 연다(5-2). 화면이 직접 ESC를 읽지 않는다.
- **[잠정]** **시간 정지는 참조 카운트**로 한다. 시간 정지가 필요한 화면이 열릴 때 +1, 닫힐 때 −1이고 0이 되면 시간이 다시 흐른다. 한 화면이 다른 화면 위에 열려도 시간이 잘못 풀리지 않는다.
- **[잠정]** 시간 정지 중에도 UI 연출은 unscaled time으로 돈다(8-2).
- **[잠정]** 화면 열기·닫기는 프리팹을 매번 생성/파괴하지 않고 **한 번 만들어 두고 활성/비활성**한다(드물게 쓰는 큰 화면만 필요할 때 로드).
- **[미정]** 스택 위에서 여러 화면이 동시에 보일 때(예: 책 위에 확인 창)의 딤 처리와 입력 막기.

### 4-A-3. 재사용 위젯과 데이터 분리

- **[잠정]** 위젯(버튼, 토글, 슬라이더, 드롭다운, 슬롯, 패널)은 **프리팹 + 테마 ScriptableObject** 조합으로 만들고, 화면은 위젯을 배치만 한다(3장, 4장). 위젯에 게임 규칙 코드를 넣지 않는다.
- **[잠정]** UI는 **게임 데이터를 읽고 이벤트를 받는 방향**으로만 연결한다(뷰는 데이터를 직접 바꾸지 않고, "이 아이템을 이 칸으로 옮겨 달라"는 요청을 보낸다). 인벤토리, 의뢰, 점수, 시간은 UI와 분리된 모델/서비스가 가지고, UI는 인터페이스로만 접근한다. (게임 규칙 문서와의 연결 지점)
- **[잠정]** 화면 텍스트는 처음부터 **키 기반**으로 가져온다(직접 문자열을 넣지 않는다). 키 구조 자체는 6장의 [미정]에서 정한다.
- **[잠정]** 설정값(의뢰 목록 표시, 소리, 화면 등)은 하나의 설정 데이터에 저장하고, 설정 페이지와 HUD가 같은 데이터를 본다.

### 4-A-4. 입력

- **[확정]** 지금 확정된 입력은 마우스(클릭, 드래그, 휠)와 키보드(ESC, Space/E)다.
- **[잠정]** 입력은 Input System 액션으로 추상화한다(6장). 키보드/게임패드로 UI를 조작(포커스 이동)하는 기능은 **지금은 만들지 않되**, 버튼을 만들 때 Selectable 기반으로 만들고 내비게이션을 막지 않아 나중에 붙일 수 있게 한다.
- **[미정]** 게임패드 지원 여부.

### 4-A-5. 성능 규칙

**캔버스와 그래픽**

- **[잠정]** 캔버스는 **자주 바뀌는 것과 정적인 것을 분리**한다. 분리 기준 예: HUD 정적 프레임 / 바 채움·화살표·타이머 / 책·인벤토리 같은 팝업(각각 별도 캔버스). 같은 캔버스 안에서 한 요소만 바뀌어도 그 캔버스 전체 메쉬가 다시 만들어진다.
- **[잠정]** 모든 UI 스프라이트는 Sprite Atlas로 묶어 드로우콜을 줄인다. 패딩과 Point 필터 설정을 확인한다(도트 가장자리 번짐 방지).
- **[잠정]** 클릭을 받지 않는 Image/TMP는 **Raycast Target을 끈다.** 버튼 등 입력을 받는 것만 켠다.
- **[잠정]** **LayoutGroup, ContentSizeFitter는 쓰지 않는다**(자주 바뀌는 곳은 특히). 크기는 10-4처럼 데이터에서 정수 픽셀로 직접 계산한다. 불가피하게 쓸 때는 정적 화면에서 한 번만 계산하고 끈다.
- **[잠정]** 스크롤 영역은 `RectMask2D`를 쓴다(Mask는 쓰지 않는다).
- **[잠정]** 크기·위치·색을 매 프레임 바꾸지 않는다. 바뀔 때(이벤트)만 갱신한다. Update에서 UI를 계속 만지는 코드를 피한다(예: 시간대 화살표는 1시간 단위 변화가 있을 때만 갱신).
- **[잠정]** Tiled 이미지(10-7 종이 패널)는 큰 크기일수록 사각형이 많이 생긴다. 작은 패널(바, 목록, 자세히, 알림)에만 쓰고, 화면 전체를 덮는 용도에는 쓰지 않는다.

**리스트와 숫자의 풀링**

- **[잠정]** 의뢰 목록처럼 개수 상한이 없는 리스트는 **보이는 항목만 재사용하는 방식(가상 스크롤 + 풀링)** 으로 만든다. 항목을 전부 만들어 마스크로 자르지 않는다. 화면에 4~5개 항목만 보이므로 풀 크기는 보이는 개수 + 여유 1~2개다. (10-2, 10-4)
- **[잠정]** 확장 인벤토리 칸(10개), 퀵슬롯(5개)은 고정 개수라서 미리 만들어 두고 내용만 바꾼다(7-4).
- **[잠정]** 점수 숫자 오브젝트는 자릿수가 바뀔 때마다 만들고 지우지 않고, **최대 자릿수(현재 4자리)만큼 미리 만들어 두고 켜고 끈다**(9-2).
- **[잠정]** 완료 알림 창이 연달아 뜰 때도 오브젝트를 미리 만든 풀에서 꺼내 쓴다(10-6).

**폰트(TMP)** — 1-1의 폰트 전략을 아래로 보완한다

- **[잠정]** **개발 중에는 Dynamic 아틀라스**(필요한 글자가 그때그때 추가), **출시 전에는 게임에 실제로 나오는 글자만 모은 Static 아틀라스**로 구워 쓴다. Dynamic은 빌드된 게임에서 처음 나오는 한글을 런타임에 래스터라이즈하며 프레임이 끊길 수 있고, 원본 TTF도 빌드에 포함해야 한다.
- **[잠정]** Dynamic을 계속 쓰는 경우에는 로딩 화면이나 시작 시점에 자주 쓰는 글자(대사, 의뢰, UI 문구)를 **미리 아틀라스에 넣어(프리워밍)** 둔다.
- **[잠정]** 텍스트가 자주 바뀌는 곳(타이머, 점수가 아닌 일반 텍스트)은 변경될 때만 SetText를 호출하고, 같은 값이면 호출하지 않는다. 문자열을 매 프레임 합치지 않는다(GC 방지).
- **[미정]** Static으로 구울 글자 목록을 만드는 방법(대사·의뢰 데이터에서 자동 추출 등). 로컬라이제이션을 하면 언어별로 다시 구워야 한다.

**기타**

- **[잠정]** 대사 Typewriter는 문자열을 매 글자 새로 만들지 않고, TMP의 `maxVisibleCharacters`를 올리는 방식으로 한다(GC와 메쉬 재생성 방지). 효과 태그는 시작 시 한 번 파싱한다(6장).
- **[잠정]** 드래그 중 아이콘은 하나의 "드래그 중" 오브젝트를 재사용하고, 맨 위(최상위 캔버스)에서 그린다(7-4).
- **[잠정]** **회전하는 스프라이트(시간대 화살표)가 있는 캔버스는 Pixel Perfect 영향과 도트 흔들림을 따로 검증**한다. 화살표만 별도 캔버스나 별도 처리가 필요할 수 있다(8-1).
- **[잠정]** 성능 검증: 에디터 Profiler로 캔버스별 리빌드(Canvas.BuildBatch)와 GC 할당을 확인한다. 팝업을 열고 닫을 때와 의뢰 100개를 넣은 테스트 목록에서 프레임이 끊기지 않는지 본다.

## 5. 책 패널 UI (book_ui)

자세한 값과 조합 방법은 `Assets/UI/book_ui/README.md`를 따른다. 요점만 기록한다.

### 5-1. 에셋 구성

- **[확정]** 구성은 왼쪽 페이지(9-slice) + 책등(가로 8px 고정) + 오른쪽 페이지(9-slice). 아이콘·텍스트는 포함하지 않는다.
- **[확정]** 책 표지(페이지 가장자리 테두리 링)는 **주황색**이다. 왼쪽 위 책 아이콘과 색을 맞췄다(밝은 `#ff8b62`, 기본 `#e66a3a`, 어두운 `#b5502d`). 처음에는 초록색이었다.
- **[확정]** 사이드 탭은 책 뒤에 그리고 왼쪽 4px가 표지 아래로 들어간다. 메뉴 개수만큼 세로로 쌓고, 꽉 채울 필요는 없다.
- **[잠정]** 탭 크기는 평상시 20×20, 선택 24×20이고 색은 6종(cream, red, amber, green, blue, purple). 아이콘 안전 영역은 12×12.
- 경계값 (L / T / R / B)

| 스프라이트 | 경계값 |
|---|---|
| book_page_left / right | 8 / 8 / 8 / 10 |
| book_spine | 0 / 8 / 0 / 10 (가로 8px 고정) |
| tab_* | 4 / 4 / 4 / 4 |
| leaf_0 / 1 / 2 | 2 / 6 / 6 / 6 |
| leaf_edge | 0 / 6 / 0 / 6 (가로 6px 고정) |
| shadow_strip | 없음 (세로로만 늘림) |

### 5-2. 용도와 여는 방법 **[확정]**

책 UI는 게임 중 **메뉴(도감·설정) 창**으로 쓴다.

- **여는 방법**: 게임 화면 **왼쪽 위의 책 아이콘을 누르거나 ESC 키**를 누르면 뜬다.
- **ESC로 열면 책의 마지막 탭인 "메뉴" 페이지(메인 화면으로 나가기, 게임 종료)가 바로 펼쳐진다.** (사용자 확정)
- **책 아이콘으로 열면 마지막에 보던 탭이 펼쳐진다.** (사용자 확정) 닫을 때 보던 탭을 기억해 둔다. **[미정]** 처음 게임을 시작해 아직 본 탭이 없을 때의 기본 탭(Claude 제안: 첫 탭인 마법 스펠). **[미정]** ESC로 열어 메뉴 탭을 본 경우도 "마지막에 보던 탭"으로 기억할지(Claude 제안: ESC로 연 것은 기억하지 않고, 탭을 직접 눌러 이동한 경우만 기억).
- **책을 열면 시간이 멈춘다.** (8-2 참조)
- **탭(사이드 라벨)에 담을 내용**:
  - **마법 스펠**: 배운 마법 주문
  - **마법진 종류**: 마법진 도감
  - **환경 설정**: 소리, 화면 등 설정 (슬라이더·토글·드롭다운 위젯을 쓴다). **의뢰 목록 표시 토글**도 여기에 둔다(10-1: 드롭다운 바를 X로 끈 뒤 다시 켜는 곳).
  - **메뉴**: 메인 화면으로 나가기, 게임 종료 (마지막 탭)
  - 위 4개 외에 더 둘 수 있다("등")
- **[잠정]** (Claude 제안, 사용자 확인 대기) 탭 순서는 마법 스펠 → 마법진 종류 → 환경 설정 → 메뉴로 하고, "환경 설정"을 마지막 탭인 "메뉴"의 바로 위에 둔다. ESC로 책을 열면 사이드 라벨에서 환경 설정이 바로 위에 보여서, 아이콘을 따로 두지 않아도 찾기 쉽다. 책 아이콘에는 마우스를 올리면 "메뉴 (ESC)" 같은 툴팁을 보여 ESC 키도 알려 주는 안을 함께 제안한다.
- **[미정]** 각 탭의 색(탭 아이콘은 어느 탭 색 위에서도 보이게 만들었다).
- **[미정]** 각 탭의 왼쪽/오른쪽 페이지 내용 배치(예: 마법 스펠 목록 + 설명). 참고로 세계관 문서의 주문은 빛, 찾아라, 느려져라, 불꽃, 자라라, 숨어라 6개다. **환경 설정 위젯, 확인 창, 주문 아이콘 6종, 마법진 도감 이미지는 책 페이지 내부 기능을 정할 때 차차 제작한다(사용자 결정).**
- **[미정]** 책을 열고 닫는 연출(표지가 열리는 효과 등), 책 안에서 ESC를 다시 눌렀을 때 닫는지.
- **[잠정]** 메인 화면으로 나가기와 게임 종료는 실수 방지를 위해 확인 창을 한 번 거친다. (Claude 제안, 미확정)
- **[잠정]** ESC는 열려 있는 UI를 위에서부터 닫는 방식으로 쓴다(자세히 패널·확장 인벤토리·대사창·팝업이 있으면 먼저 닫고, 아무것도 없을 때 책을 연다). (Claude 제안, 미확정. 자세히 패널과 확장 인벤토리는 ESC로 닫는다는 점은 10-5, 7-4에서 확정.)

### 5-3. 페이지 넘김 연출

- **[확정]** 탭을 바꾸면 페이지가 넘어가는 연출을 한다. **앞으로 넘김과 뒤로 넘김을 각각 만든다.**
- **[잠정]** 연출 값: 총 9프레임, 프레임당 약 45ms. 폭 = `round(W × |cos(π × p)|)`, p = (k+1)/10, 정수 픽셀만 사용(소수 Scale 금지). 변형은 leaf_0/1/2와 leaf_edge(k=4)를 쓰고, 반대편은 Scale X = -1로 반전한다. 페이지는 `round(4 × sin(π × p))`px 위로 들어 올린다.
- **[잠정]** 내용 교체는 넘어가는 페이지가 거의 전체를 덮는 프레임에서 한다. 앞으로 넘김은 오른쪽 내용을 k=0에서, 왼쪽 내용을 k=8에서 바꾸고, 뒤로 넘김은 반대로 한다. 선택된 탭 스프라이트는 k=0에서 바꾼다.
- **[잠정]** 멀리 있는 탭으로 이동하면 탭 사이 거리만큼 이어서 넘기고, 넘기는 동안은 탭 입력을 잠그거나 마지막 입력만 예약한다.
- **[미정]** 책을 열 때(ESC로 메뉴 탭 직행, 책 아이콘으로 마지막 탭 열기)는 넘기는 연출 없이 바로 보여 줄지, 책이 열리는 연출만 쓸지.

### 5-4. 왼쪽 위 메뉴 버튼과 탭 아이콘 (`Assets/UI/menu_icons/`)

**왼쪽 위 메뉴 버튼**

- **[확정]** 왼쪽 위에는 **책 아이콘**과 그 **옆의 가방 아이콘**을 나란히 둔다. 책은 5-2, 가방은 7-4의 UI를 연다. 환경 설정 전용 버튼은 두지 않는다(책의 탭 안으로 들어감).
- 파일 `menu_icons/buttons/btn_{book,bag}_{normal,hover,pressed}.png` (각 16×16, 배경 없음). 사용자 제공 아이콘이 원본이고, hover는 밝기 +22%, pressed는 −22%로 만든 파생이다. 눌렀을 때 위치가 움직이지 않는다(아이콘이 16×16을 꽉 채워 여백이 없음).
- 버튼은 Button의 Sprite Swap으로 상태 스프라이트를 바꿔 쓴다. 임포트는 Point, 압축 없음, PPU 16, Simple.
- **[미정]** 두 아이콘 사이 간격, 화면 모서리 여백, 아래의 의뢰 드롭다운 바(10-1)와의 간격(왼쪽 위 레이아웃은 한 번에 정한다).

## 6. 대사 UI

### 6-1. 용도와 진행
- **[확정]** 대사에는 선택지가 없다. 따라서 Yarn Spinner·Ink 같은 도구는 쓰지 않는다.
- **[확정]** Typewriter 효과로 한 글자씩 나온다. **Space/E 또는 대사 UI 마우스 클릭**으로 전체 문자가 바로 나오고, 한 번 더 누르면 다음 대사로 넘어간다.
- **[확정]** 이벤트·컷씬에서는 월드 캐릭터 머리 위 말풍선(산나비 방식)으로 표현한다. 아래 6-2의 대사창은 **크리처와의 대화(수업 등)용**이다.
- **[확정]** **대사 중 ESC는 무시한다.** 대사 도중 강제 종료되면 다음에 들어왔을 때 **그 대사가 시작되기 전 상태에서 다시 시작**한다. 예: 의뢰 재료를 다 모은 뒤 크리처에게 말을 걸었다가 강제 종료되면 "재료만 모으고 말 걸기 전" 상태로 돌아간다. (사용자 확정)
- **[잠정]** 위 규칙 구현 메모(Claude): 대사의 결과(아이템 소모, 의뢰 완료 플래그, 보상)는 **마지막 대사까지 끝난 뒤 한 번에 반영**하고, 대사 시작 시점의 상태를 기준으로 저장한다. 대사 도중에는 상태를 바꾸지 않는다.
- **[미정]** 이전 대사로 돌아가는 기능. 사용자 결정: 일단 넣지 않고 구현·테스트해 본 뒤 불편하면 추가한다. 나중에 넣기 쉽도록 대사 진행 상태를 "현재 줄 번호"로 관리한다(Claude 메모).
- **[잠정]** 대사 한 줄 데이터는 화자, 텍스트, 표정(초상화), 이벤트 키를 가진다.
- **[잠정]** 진행 상태 머신은 "타이핑 중 → 전체 표시 완료 → 다음 대사" 세 단계로 나눈다. 같은 프레임의 중복 입력을 막는다. 입력은 Input System 액션으로 추상화한다.
- **[잠정]** 대사창은 4-A의 UI 화면 스택에 `DialogueWindow`로 올리고, 시간을 멈춘다(unscaled time 사용).

### 6-2. 대사창 레이아웃 (고정 크기 스프라이트, 9-slice 사용 안 함) **[확정/잠정 혼합]**
- **[확정]** 왼쪽에 **정사각형 초상화 프레임**, 그 오른쪽에 **붙어 있는 대사 패널**. 크기가 고정이므로 9-slice 없이 고정 스프라이트로 만든다(사용자 확정). Image Type은 Simple, Native Size.
- **[확정]** 프레임 스타일은 HUD 프레임(탄색 몸통, 크림 베벨, 모브 바깥 테두리) + 안쪽 크림색 글자판.
- **[확정]** 화자 이름은 **초상화 아래 이름표에 볼드**로 표시한다.
- **[확정]** 대사창은 하단 중앙에 두고 **퀵슬롯을 덮는다.** 마력/기력 바는 오른쪽 아래 구석이라 거의 가리지 않는다.
- **[잠정]** 치수(기준 640×360): 왼쪽 열 **64×80**(초상화 창 56×56 + 구분선 2 + 이름표 56×14), 대사 패널 **320×80**. 패널을 아래에, 왼쪽 열을 위에 그려 **4px 겹치면** 이음매가 한 덩어리로 보인다. 전체 약 **380×80**, 하단 중앙 앵커, 늘리지 않는다.
- **[잠정]** 대사 텍스트: 12px, 줄 높이 16px, 최대 3줄, 한글 기준 한 줄 약 24자(글자판 안쪽 폭 약 292). 3줄을 넘으면 작성 단계에서 대사를 나누고, 에디터에서 넘침을 경고한다.
- **[확정]** 이름표 글자는 10~11px 볼드, 폭 56 안에 들어가야 한다(약 5자). **이름이 더 길면 글자 크기를 줄여서 맞춘다**(사용자 확정). **[미정]** 줄일 수 있는 최소 크기(가독성 한계)와 자동으로 줄일지(TMP Auto Size) 크리처별로 지정할지.
- **[잠정]** 다음 표시 ▼(7×4)는 글자판 오른쪽 아래 안쪽에 두고, "전체 표시 완료" 상태에서만 1px씩 끊어서 위아래로 움직인다(코드).
- **[잠정]** 초상화는 56×56 스프라이트를 프레임 **아래**에 깔고(프레임 창은 투명), 표정 키(`화자_표정`)로 교체한다. 키가 없으면 기본 표정. **초상화 없는 대사는 이 대사창을 쓰지 않고 캐릭터 머리 위 말풍선으로 처리한다**(사용자 확정, 6-3). 따라서 대사창은 항상 초상화와 이름표가 있다.
- **[잠정]** 열고 닫기: 6px 올라오며 0.12초 페이드, 위치는 정수 픽셀.

- **[잠정]** 에셋(`Assets/_Project/Art/UI/dialogue_ui/`): `dialogue_left_column.png`(64×80), `dialogue_panel.png`(320×80), `dialogue_next_arrow.png`(7×4), `portrait_placeholder_56.png`(테스트용). 이름 글자는 TMP로 위에 올린다.

### 6-3. 말풍선과 Typewriter
- **[확정]** 초상화가 없는 대사는 모두 말풍선으로 표현한다. 말풍선 UI는 대사창과 **별개로 따로 준비한다**(사용자 확정, 에셋·설계 아직 없음).
- **[잠정]** 말풍선은 월드→스크린 좌표 변환으로 추적하고, 화면 가장자리에서 클램프한다. 꼬리 방향, 여러 캐릭터 동시 대사 시 겹침 처리, 카메라 줌 대응이 필요하다.
- **[잠정]** Typewriter는 TMP의 `maxVisibleCharacters`를 올리는 방식으로 한다(4-A).
- **[미정]** Typewriter 조정 값: 기본 속도, 구두점별 지연, 글자별 효과음(blip, 음높이), 글자 등장 애니메이션, 흔들림(진폭·주파수), 오입력 방지 지연, 자동 진행 대기 시간, 화자별 프리셋.
- **[잠정]** 태그 설계(Claude 제안). 구간 태그는 시작과 끝이 있어 사이 글자에만 적용(`<shake>절대</shake>`). 지점 태그는 한 시점에만 작동(`<wait=0.5>`). 태그마다 스킵했을 때 동작(무시 / 즉시 적용 / 반드시 실행)을 정하고, 연출 이벤트는 반드시 실행한다. 태그 글자가 화면에 찍히지 않도록 시작 시 한 번 파싱해 순수 텍스트와 효과 구간 목록으로 분리한다.
- **[미정]** Sprout Lands 대화창과 "계속하려면 클릭" 스프라이트 사용 여부(6-2에서 자체 에셋을 만들었으므로 사용하지 않을 가능성이 큼).
- **[미정]** 로컬라이제이션용 텍스트 키 구조.

## 7. HUD 하단: 퀵슬롯과 상태 바

### 7-1. 퀵슬롯 (인벤토리 바)

- 출처: Sprout Lands `emojis-free/emoji style ui/Inventory/Inventory_Spritesheet.png`. 참고 레이아웃은 같은 폴더의 `inventory_example_with_slots.png`. (사용자가 `Inventory/` 하위 폴더로 옮긴 경로 기준)
- **[확정]** 스프라이트시트에서 **어두운 갈색 한 칸**을 바 배경으로 쓴다. 가로로 길게, 세로로 좀 높게 늘리되 **9-slice로 만들어 필요한 크기로 쓴다**(그냥 늘이면 테두리 굵기가 변한다).
- **[확정]** **가장 밝은 갈색 한 칸**으로 슬롯을 만들어 바 안에 가로로 배치한다.
- **[확정]** 하트 패널은 제외한다. 참고 이미지와 달리 바 안쪽의 위아래 여백을 똑같이 잡는다.
- **[확정]** 선택 중인 슬롯은 스프라이트시트 오른쪽 위의 선택 프레임(모서리 조각 세트) 중 **중간 색**으로 표시한다.
- 어두운 칸 9-slice 경계값(스프라이트시트를 픽셀 단위로 분석해 구함, L / T / R / B)

| 칸 | 크기 | 경계값 | 최소 크기 |
|---|---|---|---|
| 중간 / 큰 | 30×32 / 42×44 | 4 / 5 / 4 / 7 | 8×12 |
| 작은 | 30×32 | 4 / 8 / 4 / 9 | 8×17 |

- 이 스프라이트의 보이는 테두리 굵기는 위·좌·우 4px, **아래 6px**(입체감을 주는 밝은 줄과 그림자 때문). 9-slice는 이 굵기를 크기와 상관없이 유지한다. 아래 6px까지 없애려면 스프라이트를 수정해야 한다(수정 허용).
- **[잠정]** 슬롯 위아래 여백은 평평한 갈색이 시작되는 선에서 같게 잡는다. 슬롯 가로 w, 높이 h, 개수 n, 간격 g, 여백 m이면: 바 가로 = n×w + (n−1)×g + 2×(4+m), 바 세로 = h + 10 + 2m, 슬롯 위치 = 바 왼쪽 위에서 (4+m, 4+m). (중간/큰 칸 기준)
- **[잠정]** 퀵슬롯은 5칸이다(사용자 스케치: 지팡이가 처음 놓이는 칸 1개 + 4칸). 지팡이는 처음에 첫 칸에 있지만 **첫 칸에 고정되지 않는다.** 사용자가 "첫 칸에 없어도 돼. 일단 교체 가능하게 해"라고 정했다(7-4의 드래그 교체 대상에 지팡이 칸도 포함). 이전에 "첫 칸은 항상 지팡이" 였던 규칙은 폐기한다.
- **[미정]** 지팡이를 퀵슬롯에서 빼서 확장 칸에 두거나 빈 칸으로 두면 어떻게 되는지(지팡이 없이 마법을 못 쓰는지, 자동 복귀하는지 등. 게임 규칙 영역이라 다른 문서에서 정할 일이며, UI는 "지팡이 아이템"도 일반 아이템처럼 칸을 옮길 수 있다는 것만 보장한다). 지팡이 칸을 시각적으로 구분할지(선택 프레임 색, 간격 등)도 [미정].
- **[미정]** 슬롯 칸 크기(작은/중간/큰), 선택 프레임 구현 방식(모서리 4조각 vs 합성 프레임), 슬롯 선택 입력(숫자키·휠), 아이템 아이콘 크기.
- 수정본이면 1장의 Sprout Lands 라이선스 제약을 따른다.

### 7-3. 아이템 아이콘과 회전 방식 비교

퀵슬롯 아이템 아이콘은 슬롯 안에서 **45도 정도 기울여** 넣는다(사용자 스케치: 지팡이가 왼쪽 아래→오른쪽 위로 기울어짐). 도트 아트를 Unity에서 그냥 돌리면 도트가 깨지므로, 아래 두 방식을 같은 조건에서 **직접 비교한 뒤 하나로 정한다**.

- **[확정]** 아이콘은 UI 도트 규칙(Point, 압축 없음, PPU 16, Simple, 정수 픽셀)을 따른다.
- **[확정]** 방식 3(게임 중 런타임에 Image/Transform을 회전)은 도트가 깨져 비교 대상에서 제외한다.
- **[확정]** 사용자가 두 방식을 Unity UI 에디터 툴 씬에서 직접 비교하고 결정한다. 결정되면 이 절에 결과를 기록하고, 이후 다른 아이콘들을 같은 방식으로 제작한다.

**비교 대상**

| 방식 | 내용 | 샘플 파일 (`Assets/UI/item_icons/`) |
|---|---|---|
| 방식 1: 직접 기울여 그리기 | 45도로 기울인 상태를 도트로 직접 그린다. 에디터 작업 없음 | `item_staff.png` (16×16, Claude 제작) |
| 방식 2: 가로 원본 + 에디터 변환 | 가로 원본만 그리고, 에디터 도구가 45도로 돌려 PNG로 구워낸다 | `item_staff_horizontal.png` (26×8, Claude 제작) + **Claude Code가 만들 변환 도구** |

두 샘플은 같은 지팡이(자루 + 큐브 3덩어리 머리)지만 크기와 단순화 정도가 다르다. 방식 1은 16×16이라 머리를 하나로 뭉쳤고, 방식 2의 원본은 큐브 3덩어리를 살렸다. 비교할 때 이 차이를 감안한다.

**방식 2 변환 도구 요구사항 (Claude Code 제작)** **[잠정]**

- 위치: UI 에디터 씬의 아이템 아이콘 변환 화면(3장).
- 입력: 가로 원본 PNG. 오른쪽이 앞(머리)이고, 회전 방향은 왼쪽 아래→오른쪽 위(반시계 45도)를 기본으로 한다.
- 옵션: 회전 각도(기본 45), **회전 알고리즘 선택**, 출력 캔버스 크기(예: 16×16 / 24×24, 중앙 정렬, 투명 여백), 좌우 반전.
- 알고리즘 비교 대상:
  1. **단순 최근접 회전**(Nearest Neighbor): 기준선.
  2. **rotsprite 계열**: 원본을 정수 배(예: 8배) 확대 → 각도 회전 → 최근접으로 다시 축소. 도트 아트 회전에서 가장 깨끗한 편이라 이쪽을 기본 후보로 한다.
- 출력은 새 PNG로 저장한다(원본을 덮어쓰지 않는다). 파일명은 `원본명_rot45.png`처럼 구분하고, 임포트 설정(Point, 압축 없음, PPU 16, Simple)을 자동으로 적용한다.
- 원본에 없던 색이 생기지 않도록, 출력 색은 입력 팔레트 안의 색만 쓴다(필터 보간 금지).
- 지워지거나 끊긴 외곽선을 눈으로 확인할 수 있도록 원본·방식 1·방식 2(알고리즘별)를 한 화면에 나란히 확대(1×·4×·8×)해 보여 준다.
- 슬롯 안 실제 크기 비교 화면: 같은 슬롯 칸에 방식 1과 방식 2 결과를 넣고, 정수 배율(1×·2×·3×)과 Pixel Perfect를 켠 상태로 확인한다.

**판단 기준** **[잠정]** (Claude 제안)

1. 실루엣이 한눈에 지팡이로 읽히는가(작은 크기에서도).
2. 1px 외곽선이 끊기거나 이중선·들쭉날쭉한 계단이 없는가.
3. 자루 굵기가 일정한가(어떤 구간만 두껍거나 가늘어지지 않는가).
4. 새로운 색이 생기지 않았는가.
5. 슬롯 칸 안에 여백이 맞는가(잘림 없음, 칸 크기 변경 시 대응이 쉬운가).
6. 아이콘 하나당 제작 시간과 이후 수정 비용(각도나 칸 크기를 바꿀 때).
7. 여러 아이콘의 통일성(모두 같은 각도, 같은 방식으로 나오는가).

**비교 조건**

- 아이콘 캔버스 크기는 슬롯 칸 크기가 정해지지 않았으므로 **16×16과 24×24 두 가지로 모두** 확인한다. 방식 2의 도구는 가로 원본(26×8)을 두 캔버스에 맞춰 출력할 수 있어야 한다. (방식 1의 24×24 샘플은 아직 없으므로 필요하면 추가 제작한다.)
- 슬롯 안에서의 위치(중앙 정렬 기준)와 선택 프레임이 겹칠 때의 모습도 함께 본다.

**결정 이후 규칙** **[미정]** (비교 결과로 정한다)

- 방식 2가 충분히 깨끗하면: 모든 아이템 아이콘을 가로 원본으로만 제작하고 변환 도구로 일괄 변환한다. 가로 원본은 남겨 두어 인벤토리 패널 등 다른 각도에도 재사용한다.
- 방식 2가 깨끗하지 않으면: 아이콘을 45도 상태로 직접 그린다. 필요하면 방식 2를 초안으로 쓰고 손으로 다듬는 절충안(변환 후 수정)도 고려한다.
- 결정 내용, 확정한 캔버스 크기, 선택한 알고리즘은 이 절에 기록한다.

### 7-4. 확장 인벤토리 (가방 아이콘)

퀵슬롯을 확장해 **전체 아이템 목록**을 확인하고 정리하는 창이다.

- **[확정]** **가방 아이콘**(5-4, `btn_bag_*`)을 **책 아이콘 바로 옆**에 둔다(사용자가 "책 아이콘 옆 / 퀵슬롯 옆" 중 고민하다 책 옆으로 정함).
- **[확정]** 가방 아이콘을 누르면 확장 인벤토리가 열린다. 퀵슬롯(5칸)과, 평소 숨겨져 있던 **나머지 5칸**이 함께 **화면 중앙에 패널처럼** 뜬다.
- **[확정]** 레이아웃: 퀵슬롯 줄 **아래**에 숨겨진 5칸을 두고, 두 줄 사이에 **살짝 여백**을 둔다. 숨겨진 5칸은 퀵슬롯보다 **약간 어둡거나 밝게** 해서 구분한다.
- **[확정]** **열려 있는 동안 시간이 멈춘다**(8-2의 별도 패널 규칙).
- **[확정]** **마우스 드래그**로 아이템을 옮긴다. 빈 퀵슬롯에 장착할 수 있고, 퀵슬롯의 기존 아이템과 **교체**할 수 있다. 지팡이 칸도 교체 대상이다(7-1).

- **[잠정]** 숨겨진 칸은 한 줄 5칸(퀵슬롯 5칸과 가로 정렬이 맞음)으로 가정한다. 전체 칸 수는 10칸이다.
- **[미정]** 패널 배경(퀵슬롯 바와 같은 Sprout Lands 어두운 칸 9-slice를 쓸지, 종이 패널을 쓸지), 숨겨진 칸의 색(어둡게 / 밝게), 패널 제목·X 버튼 위치(X 버튼 스프라이트는 `quest_ui/buttons/close_*`를 재사용 가능), 칸 크기와 간격, 배경 어둡게 처리(딤) 여부, 이 창이 열려 있는 동안 HUD의 퀵슬롯 바를 그대로 보일지 숨길지, 아이템 설명 툴팁, 수량 표시, 드래그 중 아이콘 표시 방식, 빈 칸이 아닌 칸에 놓았을 때의 거부(예: 장착 불가 아이템) 처리, 아이템 버리기/사용 UI.
- **[미정]** 가방 아이콘의 별도 단축키(예: I 키)와 책 아이콘 툴팁에 단축키를 표기할지.
- 제작 필요 에셋(아직 없음): 확장 패널 배경(필요하면), 숨겨진 칸 배경(퀵슬롯 칸의 어둡거나 밝은 변형), 선택/드래그 하이라이트.

## 8. 시간대(날씨) UI

### 8-1. 표시

- 출처: Sprout Lands `emojis-free/emoji style ui/weather/Weather_UI_Free.png`를 사용자가 수정한 `Weather_UI_Free_Noon_ver.png`. 슬롯 아이콘을 **방과후와 밤**으로 바꿨다. **[확정]**
- **[확정]** 구름이 없고 하나의 날씨만 있으므로 날씨 아이콘은 왼쪽 열만 쓴다. 시간대와 날짜만 달라진다.
- **[확정]** 구성: 나무 틀 안 왼쪽 칸에 현재 시간대를 큰 아이콘으로, 오른쪽 칸에 룰렛과 화살표로 시간의 흐름을 보여 준다. 틀 아래 패널은 **날짜용**이다.
- **[확정]** 시간은 숫자 타이머가 아니라 룰렛으로 시각적으로 표시한다.
- **[확정]** 마우스를 올리면 툴팁으로 시간대(방과후/밤)와 상세 시각을 보여 준다. 시각은 1시간 단위(예: 18:00)이고, 분 단위는 어디에도 표시하지 않는다.
- **[확정]** 시간은 실시간으로 흐른다(단, 아래 8-2의 구간에서는 멈춘다). **[미정]** 현실 시간 대비 속도.
- **[확정]** 화살표는 스프라이트 한 개를 Unity에서 회전시켜 쓴다. **[미정]** 회전 방식: 도트가 뭉개지지 않도록 각도를 일정 단위로 고정하거나(스텝) 시 단위로 움직일지, 부드럽게 돌릴지. 소수 각도 회전은 도트 가장자리가 어긋날 수 있어 확인이 필요하다. (7-3의 회전 비교 결과를 참고할 수 있다.)
- **[확정]** 끝이 다가오면 화살표 색이 바뀌거나 깜빡이는 임박 효과를 준다.
  - 밤의 끝: **23:00부터** 효과 시작
  - 방과후→밤 전환: 같은 방식의 효과. **[미정]** 시작 시각
  - **[미정]** 효과 종류(색 변경 / 깜빡임 / 둘 다)와 세부 값
- **[미정]** 룰렛 분할 기준이 되는 방과후와 밤의 구간 시각.
- **[미정]** 날짜 패널에 표시할 내용(후보: N일째, 시험까지 D-n, 요일 중 일부).

### 8-2. 시간 정지 시의 UI **[확정]**

시간이 멈추는 구간(UI에 보이는 부분):

- **책(메뉴)을 열었을 때**
- **확장 인벤토리(가방)를 열었을 때**(7-4)
- **별도의 패널을 띄울 때**: 예) 의뢰 게시판 오브젝트에 상호작용 키를 눌러 의뢰 목록 패널을 띄울 때, 수락한 의뢰의 **자세히 패널**(화면 중앙)을 띄울 때(10-5)
- **크리처(NPC)와 대화하는 동안, 크리처에게 수업을 듣는 시간**

개발 중에는 시간이 멈춰 있으면 "멈춰 있음" 텍스트를 화면에 표시한다(디버그용). **[미정]** 정식 빌드에서 숨길지 여부(기본은 숨김으로 가정).

**[잠정]** (Claude 제안) UI 연출(페이지 넘김, 타이핑 효과, 말풍선)은 시간이 멈춘 동안에도 재생되어야 하므로, 게임 시간을 멈출 때 `Time.timeScale = 0`을 쓴다면 UI 연출은 unscaled time으로 재생한다.

의뢰 게시판 패널(의뢰 목록 패널)은 별도 UI로 새로 필요하다. **[미정]** 디자인과 내용 구성. 수락한 의뢰 드롭다운은 10장에서 정리했다.

시간 규칙 자체(정지 범위, 경비원 판정 등)는 이 문서의 범위가 아니다.

## 9. 점수 UI (실기 예상 점수 / 필기 예상 점수)

플레이어의 **실기 예상 점수**와 **필기 예상 점수**를 보여 주는 UI다. 점수 계산 규칙과 통과 기준 자체는 이 문서의 범위가 아니고, 여기서는 **어떻게 보여 줄지**만 다룬다.

### 9-1. 표시 방식 결정

- **[확정]** 실기와 필기, 두 가지 점수를 각각 표시한다.
- **[확정]** 점수 UI는 **숫자 텍스트**로 만든다(스탯 바 아님). 숫자는 스프라이트 숫자(0~9)를 조합해 예상 점수에 맞춰 보여 주고, 숫자 아래에 마커로 그은 듯한 두 줄 밑줄을 붙인다.
- 결정 배경(사용자 고민): 목표치를 채우는 바(예: 1/100)냐, 상한 없이 쌓는 점수에 통과 기준을 시스템만 아느냐. D-N일마다 세이브를 남겨 엔딩 후 돌아가 다양한 엔딩(실기 부족, 필기 부족 등)을 보게 할 계획이라 후자(상한 없는 점수 + 숨긴 통과 기준) 쪽으로 정했다. 점수 규칙 자체는 다른 문서에서 다룬다.
- **[미정]** 엔딩 화면에서 기준 점수와의 차이를 정확한 숫자로 알려 줄지, 말(문구)로만 알려 줄지. (Claude 제안: 정확한 숫자로 보여 주면 세이브로 돌아가는 동기가 생긴다.)
- **[미정]** 플레이 도중 거친 힌트(선생님 평가 문구, 위험/아슬아슬/안정 등급)를 줄지.
- **[미정]** 새로 필요한 UI: 엔딩 화면(내 점수와 기준 점수 비교), 세이브 복귀 화면(D-N 세이브 목록).
- **[미정]** 점수 UI의 HUD 안 위치(항상 표시할지, 책 UI 탭 안이나 별도 패널에서만 볼지).
- **[미정]** "예상" 점수라는 이름의 의미를 UI에서 어떻게 표현할지(추정치임을 나타내는 표기).

- **[잠정]** 숫자 조합: 칸 폭 11px, **칸 간격 -2px**(피치 9, 글자 사이가 1px 비어 보임). 자릿수 n이면 숫자 전체 폭 = 9n+2. 숫자 위에 밑줄을 가로 중앙으로 맞춰 바로 아래(숫자 아래 12px 줄 바로 다음)에 붙인다. 1자리 숫자에도 밑줄 2를 쓰므로 밑줄이 숫자보다 꽤 넓어진다.
- **[잠정]** 임포트: Point, 압축 없음, PPU 16, Simple. 시트는 Multiple에서 11×12 칸 단위로 자른다. 위치는 정수 픽셀로 맞춘다(홀수 폭 중앙 정렬은 0.5px 어긋날 수 있다).
- **[잠정]** 숫자 오브젝트는 최대 자릿수(4)만큼 미리 만들어 두고, 자릿수가 바뀌면 켜고 끄며 밑줄 스프라이트를 교체한다(만들고 지우지 않는다, 4-A-5).
- **[미정]** 5자리 이상(10000점 이상)이 필요한지. 필요하면 밑줄을 새로 만든다.
- 확인 이미지: `score_ui/_preview/score_final_combo_4x.png`(위: 필기=ver1 밑줄, 아래: 실기=ver2 밑줄, 숫자는 ver2).

## 10. 수락한 의뢰 목록 드롭다운 UI

의뢰 게시판 패널과는 별개의 HUD 요소다. 게시판에서 수락한 의뢰를 평소에도 확인하는 용도다. 사용자가 "나머지는 만들면서 차차 구상하겠다"고 해서, 아래 [미정]은 에셋 제작·구현 중에 정한다.

### 10-1. 바와 펼침/접힘

- **[확정]** **드롭다운 바가 평소에도 화면 위에 떠 있다.** 바의 **맨 왼쪽**에 화살표 아이콘이 있다.
  - 접힌 상태: **아래 화살표** 아이콘. 누르면 목록이 아래로 펼쳐진다.
  - 펼친 상태: 같은 위치에서 **위 화살표** 아이콘으로 바뀌고, 누르면 목록이 다시 접힌다.
- **[확정]** 접힌 상태의 바에는 **제목 + 의뢰 개수**를 보여 준다(예: `수락한 의뢰 (3)`). 접으면 목록 항목은 하나도 보이지 않는다.
- **[확정]** 펼침/접힘은 **연출 없이 즉시** 바뀐다.
- **[확정]** 위치: **화면 왼쪽 위, 책·가방 아이콘 묶음 아래.**
- **[확정]** 바의 **오른쪽 끝에 X(닫기) 버튼**이 있다. 이 X는 **목록만 접는 것이 아니라 드롭다운 바 전체를 화면에서 끈다.** 끈 뒤에는 **환경 설정 등에서 다시 켤 수 있어야 한다.**
  - 책의 환경 설정 페이지에 "의뢰 목록 표시" 토글을 둔다(5-2). 켜짐/꺼짐 상태는 저장한다(세이브/설정 데이터).
  - **[미정]** 꺼져 있는 동안 새 의뢰를 수락하거나 의뢰를 완료했을 때 알림(10-6)은 계속 보일지.
- **[미정]** 드롭다운을 펼치고 접는 동안 시간이 멈추는지. (HUD라서 멈추지 않는 쪽을 Claude가 제안. 8-2의 시간 정지는 자세히 패널에만 적용한다고 가정.)

### 10-2. 목록 패널과 항목

- **[확정]** 펼치면 지금 수락해서 해야 하는 의뢰들이 **항목(텍스트 박스)으로 정렬**되어 보인다.
- **[확정]** 한 항목에는 **의뢰 제목 + 진행 상황**을 보여 준다.
- **[확정]** 드롭다운 패널의 **위아래 길이는 항목(텍스트 박스)에 맞춰 달라진다.** 최상단 항목 위 패딩과 최하단 항목 아래 패딩은 **항상 같다.**
- **[확정]** **패널 가로 길이는 고정, 세로만 가변.**
- **[확정]** 시각 톤: **책 UI와 같은 크림색 종이 패널.** 가장자리는 깔끔하고 **찢어진 곳은 변마다 한두 군데뿐**이다(처음 시안이 너무 낡아 보여 수정함). 얼룩 같은 낡은 질감은 쓰지 않는다.
- **[확정]** 동시에 수락할 수 있는 의뢰 개수에 **상한이 없다.** 목록이 길면 **스크롤**한다.
- **[확정]** 패널 최대 높이는 **항목이 대략 4개 보일 때**로 잡는다. 이보다 많으면 스크롤한다.
- **[확정]** 스크롤은 **마우스 휠 + 작은 스크롤바 표시**.

### 10-3. 정렬과 색상

- **[확정]** **완료한 의뢰는 다른 텍스트 색상**을 가지며 **목록 가장 위로 올라온다.**
- **[확정]** 정렬 우선순위: **완료 → 진행률(높은 순) → 수락한 순서.** (완료한 의뢰가 맨 위, 그 안에서는 진행률이 높은 순, 같으면 먼저 수락한 순.)
- **[미정]** 완료 항목과 일반 항목의 텍스트 색상 값, 항목 간 구분선·간격.
- **[미정]** 완료 항목에서 진행률이 같거나 100%일 때의 정렬(수락 순으로 처리해도 되는지).

### 10-4. 패널 높이 계산 (Claude 구현 메모, **[잠정]**)

- 패널 높이 = 위 패딩 + Σ(항목 높이) + (n−1)×항목 간격 + 아래 패딩. 위·아래 패딩은 같은 상수 하나를 쓴다. 높이는 정수 픽셀로 맞춘다. 항목 높이는 줄 수에 따라 달라지므로 레이아웃이 계산한 값을 정수로 올림한다. 패널 크기는 목록이 바뀌거나 펼칠 때만 갱신한다(매 프레임 X). 패딩은 9-slice 안쪽 평평한 영역이 시작되는 선 기준으로 잡는다(7-1과 같은 방식).
- **최대 높이를 넘으면** 패널 높이를 최대 높이로 고정하고, 목록은 마스크(RectMask2D)로 잘라 스크롤한다. **항목은 보이는 개수(4~5개) + 여유만 풀에서 재사용하는 가상 스크롤로 만든다**(상한 없는 목록이라, 4-A-5).
- 완료 여부·진행률·수락 순서는 데이터로 두고 정렬한다. 정렬은 목록이 바뀔 때만 한다.

### 10-5. 자세히 패널 **[확정/잠정 혼합]**

- **[확정]** 목록의 항목을 누르면 **자세히 보여 주는 패널**을 띄운다(사용자가 설계 방향으로 말함).
- **[확정]** 자세히 패널은 **화면 중앙**에 띄우고, **시간이 멈춘다**(8-2의 별도 패널 규칙).
- **[확정]** **닫는 방법: X 버튼, 그리고 ESC.** (사용자 확정. X 버튼 에셋은 드롭다운 바와 같은 것을 쓴다.)
- **[잠정]** 내용: 의뢰 제목, 크리처 대사 한 줄, 진행 상황, 아이템 아이콘, 보상. (사용자가 "생각 중"이라고 한 구성.)
- **[잠정]** 아이템 아이콘은 **모르는 아이템이면 도감처럼 회색 처리**하는 안(사용자 의견, 확정 아님).
- **[미정]** 패널 크기, 보상 표시 형식, 바깥 클릭으로도 닫을지.

### 10-6. 완료 알림 창 **[확정/잠정 혼합]**

- **[잠정]** 의뢰를 **완료하는 순간**, 어느 의뢰를 완료했는지 **잠시 보이는 작은 창**으로 알린다(사용자가 "생각 중"이라고 한 기능).
- **[확정]** 위치: **화면 왼쪽 아래.**
- **[미정]** 표시 시간, 사라지는 연출, 여러 건이 연달아 완료될 때 쌓는 방식, 소리.
- 주의: 왼쪽 아래는 퀵슬롯·상태 바 위치와 겹치지 않는지 7장 레이아웃 확정 때 확인한다(상태 바 위치 [미정]).

## 11. 확인 필요 사항 (UI 범위)

- Sprout Lands는 비상업 전용이다. 상업 전환 가능성에 따라 교체 계획이 필요하다.
- 마력 아이콘, 책·가방 아이콘, 16×16 주황 패널의 출처·라이선스.
- **갈무리11, 스타더스트 3.0의 라이선스(상업 사용 가능 여부)**, 두 폰트의 설계 크기와 한글 글리프 완비 여부(1-1).
- 월드 카메라 투영 방식(원근/직교)에 따라 스프라이트 레이어의 도트 밀도가 달라진다.
- 에디터 씬의 범위(개발 전용 여부).
- ESC를 대사창·팝업과 겹쳐 쓸 때의 우선순위(5-2의 제안 확정 필요).
- 책 탭 순서(환경 설정을 메뉴 바로 위에 두는 안) 확인, 첫 실행 시 책 아이콘의 기본 탭, ESC로 본 메뉴 탭을 "마지막 탭"으로 기억할지(5-2). 책 아이콘 툴팁 안.

- 상태 바의 높이·위치·수치 표시 방식(7-2의 [미정] 항목). 완료 알림 창(왼쪽 아래)과 겹치지 않는지 함께 확인.

- 점수 UI: 엔딩 화면에서 기준 점수 차이를 정확한 숫자로 보여 줄지, 힌트 여부, HUD 위치(9-1).
- 의뢰 드롭다운: 텍스트 색상, 자세히 패널 세부, 완료 알림 세부, 드롭다운 중 시간 정지 여부, 바를 끈 상태에서의 알림(10장 [미정]). 종이 패널 Tiled의 Border 반복 동작 확인(10-7).

- 폰트 비교 후 최종 폰트와 크기 확정(1-1).
- 책 페이지 내부 기능(환경 설정 위젯, 확인 창, 주문 아이콘 6종, 마법진 도감)은 차차 설계·제작.
