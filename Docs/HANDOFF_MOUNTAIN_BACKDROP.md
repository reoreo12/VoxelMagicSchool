# 인수인계 — 뒷산 배경 바위산(봉우리 청크) 설계·제작

> 작성: 2026-11-11, 브랜치 `Back-mountain-map`. 앞선 "뒷산 바닥" 작업 대화에서 넘겨받는 문서.
> 이 문서만 읽고 바로 설계에 들어가면 된다. 바닥 제작 과정을 다시 조사할 필요 없음.

## 1. 이번 목표
- 포획 구역에서 크리처 굴 옆·뒤까지 **전부 덮는 배경 바위산**(풀 덮인 바위산)을 복셀 FBX 청크로 제작. 봉우리마다 청크를 나눠 컬링한다.
- 화풍·ppu·팔레트 색감은 FarmPond 및 뒷산 바닥과 통일. 불투명 단색 복셀, 팔레트 1장.
- 참고 이미지(사용자가 새 대화에 직접 첨부): ① FarmPond 화풍 스크린샷 ② ~⑤ 한국 화강암 바위산(둥근 암반 돔, 세로 결 바위, 소나무, 풀·숲 덮임) ⑥ 게임 카메라 시점 참고.
- 진행 순서: **설계를 이미지로 보여 주고 → 사용자 승인 → 제작.** 제외 항목은 설계 때 사용자에게 먼저 확인.

## 2. 현재 맵 상태 (확인 필요 항목 포함)
- 뒷산 바닥은 청크 9개(T, A1~A3, B, C1~C3, D)로 제작 완료. **사용자가 게임 중 C3, D 청크를 껐다** (포획 구역에서 굴까지 너무 멀어서). 따라서 **크리처 굴은 지금 B/C1/C2 쪽 가까운 곳에 놓일 가능성이 크다.** 굴의 실제 위치는 새 대화 시작 시 사용자에게 묻거나 `BackMountain.unity`에서 확인할 것 (추측 금지).
- 월드 로컬 좌표: +Z = 화면 왼쪽 위, +X = 오른쪽 위, 입구 남쪽(z = −5), 입구 윗면 y = 0.
- 청크 배치 (x, 0, z): T(5,−5) A1(0,0) A2(0,16) A3(0,32) B(0,48) C1(16,48) C2(32,48) C3(48,48) D(64,48). 청크 16×16 m (T만 6×5 m).
- 포획 구역: B 북쪽 (x 0~16, z 64~80), 평지 높이 약 4.2 m. 포획 프로토타입 지침은 `Docs/BACKMOUNTAIN_PROTOTYPE_GUIDE.md`.
- 길 높이: 입구 0 m → B 4.2~4.7 m → C1 6.1 → C2 8.2 → C3 10.3 → D 11.2 m. 길 폭 약 3 m.
- 씬: `Assets/_Project/Scenes/BackMountain.unity` (루트 `MountainFloor` 아래 청크 FBX 9개, FarmPond와 같은 조명, 임시 Main Camera). 설계 문서: `Docs/DESIGN_MOUNTAIN_FLOOR.md`.

## 3. 기술 규격 (바닥과 동일하게)
- 복셀 1칸 = **0.0667 m** (1 m = 15복셀). 청크 크기는 봉우리 크기에 맞춰도 되지만 한 변 256복셀(약 17 m) 이하면 .vox 확인이 쉽다.
- 메시: greedy 메싱 → npz(V, N, C) → 팔레트 UV(256×1 팔레트, u = (idx+0.5)/256) → Blender → FBX → Unity.
- Blender 3.0.1, `blender_bridge`의 `run_python` 사용. 정점 매핑 (bx,by,bz) = (−x,−z,y), 면 루프 순서 [0,3,2,1], FBX 내보내기 `FBX_SCALE_ALL`, `bake_space_transform=True`, axis_forward '−Z', axis_up 'Y', 내보내기 직전 `view_layer.update()` 필수 (콜렉션 `MtExport` + use_active_collection). **Blender 스크립트에서 `np.load`한 NpzFile은 반드시 닫을 것**(안 닫으면 파일 삭제·이동이 막힌다).
- Unity 임포트: 스케일 1, 회전 0, 콜라이더 없음, 메시 압축 끔, 머티리얼은 `Mountain_Voxel`로 리맵.
- 바닥 제작 스크립트는 프로젝트에 있음: `Assets/_Project/Art/Map/Mountain/Source/hf.py`(높이장·팔레트), `gen_mesh.py`(greedy 메싱·.vox·팔레트 PNG). 새 스크립트는 이를 재사용하면 된다. (미리보기 렌더 스크립트는 프로젝트에 없음)
- 팔레트: `Mountain_palette.png`(256×1, Point, 밉맵 없음, 무압축, Clamp) + `Mountain_Voxel.mat`(URP Lit, `_BaseMap` = 팔레트). 기존 칸 번호는 바꾸지 말고 **새 색은 뒤 칸에 추가**하면 기존 FBX가 안 깨진다.
- 기존 색: 길 #8A5A36, 외곽선 #4C321E, 흙 #6A4A33(+#5B3F2B), 이끼 #507848(+#386038, #5F8A52), 단면 #4A3322 / #3A281C. FarmPond 아틀라스에서 직접 읽은 값이다.
- 게임 카메라: yaw 45°, pitch 55°, fov 60, 거리 약 12 m(줄일 예정). 즉 **카메라는 남서쪽에서 북동쪽을 내려다본다** → 배경 바위산에서 보이는 면은 **윗면, −X면, −Z면**뿐이다.
- 검증 방법(싸고 확실): Unity `execute_code`로 추가 씬을 열고 임시 Camera → RenderTexture → PNG를 프로젝트 `Temp/`에 저장 → `device_stage_files`로 가져와 확인. 화면 캡처보다 수치(바운드·삼각형 수) 확인을 우선.

## 4. 사용량 절약 제안 (사용자가 수락함)
1. **뒷면은 만들지 않는다.** 카메라에서 안 보이는 +X면, +Z면, 아랫면은 생성하지 말고 평평하게 잘라 둔다(바닥 단면과 같은 방식). 삼각형과 작업량이 크게 줄고, 청크마다 약 절반의 면이 사라진다.
2. **봉우리 1개를 반전해 재활용한다.** 자연스러우면 충분하다는 것이 사용자 의견. 단, **반전은 FBX가 아니라 높이장 단계에서** 한다 (X↔Z 뒤집기, 90° 회전 대신 거울 반전). 이유: FBX에서 음수 스케일로 뒤집으면 면 방향이 뒤집히고, 보이는 면(−X, −Z)이 카메라 반대쪽으로 가 버린다. 거울 반전한 높이장에서 **보이는 면 규칙을 다시 적용해** 메시를 생성할 것. 시드·크기·높이 비율만 달리해도 변형이 충분히 나온다.
3. **색은 이끼 팔레트를 재사용한다.** 풀 덮인 부분은 #507848 / #386038 / #5F8A52, 흙 틈은 #6A4A33. 바위 색만 새 칸으로 추가한다. 제안값(조정 가능): 바위 밝음 #B5AA9A, 바위 기본 #9A8F82, 바위 어둠 #7C7268, 갈라진 틈 #5E564E. 사진 ②~⑤의 연한 베이지 회색 화강암 느낌.
4. **설계 이미지는 1장짜리 종합 시트로**: 봉우리 3~4종의 게임 카메라 시점 미리보기 + 포획 구역~굴과의 배치 평면도. 별도 렌더러를 새로 짜지 말고, 초안 메시를 Unity에서 임시 카메라로 렌더하는 편이 싸다.
5. **수정 요청은 한 번에 모아서 반영**하고, 제작은 봉우리 1개를 끝까지 만들어 Unity에서 확인한 뒤 나머지를 같은 스크립트로 찍어낸다.
6. 거리감: 배경은 플레이어가 올라갈 수 없는 장식이므로 콜라이더 없음. 단면 두께·아랫면 처리 불필요. 필요하면 먼 봉우리는 복셀 해상도를 같게 유지하되 세부(잔 바위 결)를 줄여 삼각형을 아낀다. 삼각형 예산은 바닥 청크 수준(청크당 4~5만)을 상한으로.

## 5. 설계 때 정할 것 (사용자에게 한 번에 묻기)
- 크리처 굴의 현재 위치와 모양(바위 덮임을 굴 입구까지 허용할지, 굴 입구 주변은 비워 둘지).
- 배경 바위산이 덮을 범위: 포획 구역 북쪽·동쪽 전부인지, 길 바깥쪽 둘레까지인지. 길·포획 구역과 겹치면 안 됨.
- 봉우리 수·최대 높이(플레이어 카메라 위로 어디까지 솟을지), 소나무 같은 식생을 이번 범위에 넣을지(기본: 제외, 풀·이끼 덮임만).
- 바닥과 이어지는 경계 처리(바닥 바깥 단면 위에 얹는지, 바닥 끝에서 시작하는지).
