# 의뢰 시스템 정식 개편 + 게임 타이머 + 치트

## 배경
이 프로젝트는 **"복셀 한국 마법 학교 게임(가제)"** 실제 게임 프로젝트다. 프로토타입 1에서 만든 의뢰·농사·낚시 루프의 **의뢰 시스템을 정식 규칙으로 개편**하고, 하루 시간을 관리하는 **게임 타이머**와 개발·촬영용 **치트**를 만든다.

### 게임 흐름 요약 (이번 작업에 필요한 만큼)
- 마법 열등생이 8일째 급수 시험을 앞두고, 뒷산 크리처 굴에서 밤마다 과외(실기 점수)를 받고 의뢰를 전달(필기 점수)한다.
- 방과 후에는 텃밭(농작), 연못(낚시), 뒷산(채집)에서 의뢰 재료를 모은다. 밤에는 굴에 가서 의뢰를 전달하고 새 의뢰를 받는다.
- 화폐는 없다. **시간이 핵심 자원**이다. 한 회차 목표 플레이 시간은 **약 1시간**이다.

### 8일 일정
| 날짜 | 낮 | 방과 후 | 밤 | 시간 흐름 |
|---|---|---|---|---|
| 1일 | 첫 수업 → 소문 (스토리) | 스토리 | 크리처와 만남 + 과외(빛) + **튜토리얼 의뢰** | 흐르지 않음 |
| 2일 | — | 자유 | 의뢰 + 과외 | 흐름 |
| 3일 | 아침 지각 레이스 (이벤트) | 자유 | 의뢰 + 과외 | 이벤트 중 멈춤, 방과 후부터 흐름 |
| 4일 | 점심 마법 대결 (이벤트) | 자유 | 의뢰 + 과외 | 위와 같음 |
| 5일 | 낮 석고상 보스전 (이벤트) | 자유 | 의뢰 + 과외 | 위와 같음 |
| 6일 | — | 자유 | **마지막 의뢰 전달** + 과외 | 흐름 |
| 7일 | — | 축제 구경 (선택) | 불꽃놀이 | 흐르지 않음 (스토리) |
| 8일 | 급수 시험 → 엔딩 | | | 흐르지 않음 |

- 이벤트 자체와 1·7·8일의 스토리 구간은 **이번 작업 범위가 아니다.** 타이머는 이런 날과 구간에서 시간을 멈추고, 끝나면 정해진 시각으로 넘어갈 수 있는 기능만 제공한다.
- 포획 시스템은 게임에 넣을지 **보류 중**이다. 의뢰 재료에 포획 재료를 넣지 않되, 나중에 재료 출처를 추가할 자리는 남긴다.

## 0. 설계 먼저, 승인 후 제작 (가장 중요)
`CLAUDE.md`의 규칙을 그대로 따른다. 특히 아래 세 가지를 지킨다.
- 시작할 때 **프로토타입 1의 현재 코드와 `Docs/DESIGN.md`를 먼저 읽고**, 의뢰·인벤토리·텃밭·낚시·점수 관련 클래스가 지금 어떻게 되어 있는지 요약해서 알려 준다.
- 코드를 만들기 전에 `Docs/DESIGN_QUEST_TIMER.md`로 설계를 정리해 대화에서 설명하고, 내가 **"제작 시작"**이라고 말하면 그때 만든다.
- 모든 스크립트 맨 위에 용도와 의도를 주석으로 적는다 (최대 3줄, 짧으면 1줄).

### 설계 단계에서 보여 줄 것
1. **프로토타입 1에서 바뀌는 점 표**: 기존 클래스 / 그대로 둠·수정·교체·삭제 / 이유
2. **클래스 목록 표**: 이름 / 종류 / 어셈블리 / 한 줄 역할
3. **상속·구현 구조도** (텍스트 트리)
4. **상태 다이어그램 두 개**
   - 의뢰 하나의 상태: 게시판 → 수락(진행 중) → 완료 가능 → 전달됨 / 포기 / 만료(게시판에서 사라짐)
   - 하루의 흐름: 하루 시작 → 방과 후 → 밤 → 하루 끝 (멈춤·스토리 구간 포함)
5. **이벤트(알림) 목록**: 누가 발행하고 누가 구독하는지 (예: 시각 변경, 시간대 변경, 하루 시작, 임박 경고, 의뢰 상태 변경)
6. **데이터 목록**: 만들 ScriptableObject와 예시 값
7. **확장 지점**: 세이브(D-N 날짜별 저장), 포획 재료 추가, 이벤트 결과로 다음 날 시작 시각 변경, 장르 이벤트·스토리 날 연결, 밤 길이 조정
8. **설계에서 고민한 선택지**와 고른 이유

**"제작 시작" 승인 전에는 스크립트, 씬, 에셋을 만들지 않는다.** (읽기만 하는 작업은 괜찮다.)

## 1. 게임 타이머

### 1-1. 하루 구간과 속도 (모두 설정 에셋에서 조절)
| 구간 | 게임 시각 | 현실 시간 (기본값) |
|---|---|---|
| 방과 후 | 16:00 ~ 20:00 | 3분 30초 |
| 밤 | 20:00 ~ 24:00 | 2분 30초 |
| **하루 합계** | | **약 6분** |

- 구간마다 **시작 시각, 끝 시각, 현실 시간(초)**을 데이터로 가진다. 구간마다 속도가 다를 수 있다 (기본값 기준 방과 후는 게임 1시간 = 52.5초, 밤은 37.5초).
- 시간이 흐르는 날은 2~6일 (5일 × 약 6분 = 약 30분)이다. 나머지는 스토리·이벤트 콘텐츠다.
- 시간대는 **방과 후 / 밤** 두 가지다. 날씨는 하나뿐이다.

### 1-2. 시간이 멈추는 때와 흐르는 때
| 멈춤 | 흐름 |
|---|---|
| 책(메뉴), 가방(확장 인벤토리)을 열었을 때 | 걷기, 이동 |
| 의뢰 게시판 목록 패널, 의뢰 자세히 패널 등 별도 패널을 띄웠을 때 | 낚시 (던지기·입질·미니게임 포함) |
| 크리처와 대화할 때, 과외를 받을 때 | 마법진 그리기 |
| 스토리·이벤트 구간, 1·7·8일 | |

- 채집 줍기와 맵 이동(문 연출 + 페이드)은 시간을 따로 쓰지 않는다.
- 여러 원인이 겹쳐도 꼬이지 않도록, 멈춤은 **원인별로 등록하고 해제**하는 방식으로 만든다 (모든 원인이 해제되어야 다시 흐름).
- UI 연출(페이지 넘김, 타이핑 효과, 말풍선)은 멈춘 동안에도 재생되어야 한다. `Time.timeScale`을 쓴다면 UI 연출은 unscaled time으로 돈다. 게임 시계 자체는 `Time.timeScale`과 별개로 멈출 수 있게 설계한다.
- 개발 중에는 시간이 멈춰 있으면 화면에 "멈춰 있음"과 멈춘 원인을 표시한다 (디버그 표시, 정식 빌드에서는 숨김).

### 1-3. 알림 시각
- **19:00**: 방과 후 → 밤 전환 임박 경고
- **23:00**: 밤의 끝 임박 경고
- 경고 시각도 설정 에셋에서 조절한다. UI(시간대 룰렛의 화살표 색 변경·깜빡임)는 이 알림을 구독만 한다.

### 1-4. 하루의 시작과 끝
- **하루 시작 = 방과 후가 시작되는 순간**이다. 이때 순서대로 처리한다.
  1. 작물이 하루만큼 자란다.
  2. 채집 재료가 새로 생긴다 (3-2).
  3. 의뢰 게시판이 새 의뢰로 바뀐다. 받지 않은 의뢰는 사라진다 (2-2).
- **밤 24:00이 되면** 경비원에게 걸린 것으로 처리하고 다음 날로 넘어간다. **다음 날 방과 후는 1시간 늦게 (17:00) 시작**한다.
- **다음 날 시작 시각 변경 기능**: 다른 시스템(장르 이벤트 결과, 경비원)이 "다음 날 방과 후 시작을 N분 늦게/일찍"을 요청할 수 있게 한다. 예: 지각 레이스 승리 15:30, 패배 16:30, 석고상 패배 17:00, 경비원 17:00. 같은 날 여러 요청이 오면 합칠지 가장 큰 값만 쓸지는 설계에서 제안한다.
- [미정] 24:00 전에 플레이어가 스스로 하루를 끝낼 수 있는지 (방으로 돌아가 자기 등). 설계에서 방법을 제안하되, **기본 동작은 24:00까지 흐르는 것**으로 만든다.

### 1-5. 날짜
- 1일부터 8일까지 센다. 날짜마다 **날 종류**(스토리 날 / 이벤트 날 / 자유 날)를 데이터로 정한다.
- 이벤트 날은 이벤트가 끝난 뒤 방과 후부터 시간이 흐른다. 이번 작업에서는 이벤트를 "건너뜀" 처리하고 바로 방과 후로 시작하는 임시 흐름만 둔다.
- 화면에 표시할 정보(시간대, 1시간 단위 시각, 날짜 N일째, 시험까지 D-n)를 읽기 전용으로 제공한다. 분 단위는 UI에 표시하지 않는다.

## 2. 의뢰 시스템 (정식 규칙)

### 2-1. 의뢰 데이터
- 의뢰 하나: 제목, 크리처 대사(의뢰 설명), **서식지 힌트 한 줄**, 필요 재료 목록(재료 + 개수, **합계 최대 3개**), 난이도, 수락 시 지급할 씨앗, 전달할 때 크리처 대사(재료 설명 = 필기 공부).
- 의뢰는 ScriptableObject로 만들고, 코드를 고치지 않고 추가할 수 있어야 한다.
- 재료(아이템)에는 **희귀도**(흔함 / 보통 / 희귀)와 **출처**(농작 / 낚시 / 채집 / 포획-보류)가 있다.

### 2-2. 게시판
- 게시판은 **크리처 굴 안**에 있다. 밤에 굴에서 목록을 열어 수락한다 (패널을 여는 동안 시간 멈춤).
- **하루 시작 때 새 의뢰 3개**로 바뀐다. 받지 않은 의뢰는 그때 사라진다.
- 3개는 난이도별로 하나씩 고른다.

| 난이도 | 구성 | 등장 |
|---|---|---|
| 쉬움 | 흔한 재료 1~2개 | 매일 |
| 보통 | 보통 재료 1개 + 흔한 재료 1~2개 | 매일 |
| 어려움 | 희귀 재료 1개 + 다른 재료 1~2개 | 2일부터 (2026-11-25 변경: 의뢰 튜토리얼은 1일에 끝나므로) |

- 1일은 튜토리얼 의뢰 1개로 고정한다 (2-6).
- 의뢰 전달이 가능한 마지막 밤은 **6일 밤**이다. 7일 이후에는 게시판을 열지 않는다.
- 같은 의뢰가 너무 자주 반복되지 않도록 뽑는 규칙을 설계에서 제안한다.

### 2-3. 수락과 보관
- 동시에 받아 둘 수 있는 의뢰는 **최대 3개**다 (설정에서 조절). 꽉 차 있으면 새 의뢰를 받을 수 없고, 이유를 안내한다.
- 의뢰는 **크리처에게 전달해야 칸이 빈다.** 재료를 다 모아 "완료 가능" 상태가 되어도 전달 전까지는 칸을 차지한다.
- **수락하면 그 의뢰에 필요한 작물의 씨앗을 준다.**
- **씨앗 다시 받기**: 나중에 인벤토리에 버리기 기능이 생겨 씨앗을 잃었을 때를 대비해, 진행 중인 의뢰에 필요한 씨앗이 인벤토리에 없으면 게시판이나 크리처에게서 다시 받을 수 있게 한다. 무한히 받아 가는 악용을 막는 규칙(예: 이미 심은 만큼은 빼고 지급)을 설계에서 제안한다.
- 기존 프로토타입의 "진행 중에는 두 번째 의뢰를 받을 수 없다" 규칙은 삭제한다.
- UI 문서에 "의뢰 개수 상한 없음"으로 적힌 내용이 있다면 이 지침(최대 3개)이 우선한다.

### 2-4. 포기
- 의뢰 목록 UI(드롭다운)의 자세히 패널, 또는 책 메뉴의 의뢰 상세 페이지에서 **포기 버튼**으로 포기한다. 실수 방지용 확인 창을 띄운다.
- 포기하면 칸이 빈다. 받은 씨앗은 회수하지 않는다.
- [결정 2026-11-25] 포기하면 그 의뢰가 준 씨앗을 **가방에 있는 만큼, 준 개수까지** 회수한다. 이미 심은 씨앗·작물은 회수하지 않는다(설계 7-8). 그 밖의 손해 없음.
- [결정 2026-11-25] 덜 자란 작물 파내기를 넣게 되면 파낸 씨앗은 가방에 돌려준다(설계 7-6).
- [미정, 위 결정 전 원문] 포기의 손해(기본: 없음), 포기한 의뢰가 게시판에 다시 올라오는지(기본: 사라짐).
- 책 메뉴의 의뢰 상세 페이지 UI는 이번 범위가 아니다. **포기 기능은 UI와 분리된 메서드**로 만들어, 어느 화면에서든 호출할 수 있게 한다.

### 2-5. 진행과 전달
- 인벤토리의 재료가 바뀔 때마다 진행 상황(예: `대파 2/2`, `붕어 0/1`)을 다시 계산하고 알린다. 드롭다운 UI는 이 알림을 구독한다 (정렬: 완료 → 진행률 높은 순 → 수락 순).
- **필요한 재료를 모두 모아야만 제출할 수 있다.** 일부만 먼저 낼 수 없다.
- **전달 흐름**: 크리처와 대화를 시작하면 → 지금 완료 가능한 의뢰 목록에서 하나를 고른다 → 크리처가 재료 설명 대사를 하고 → 재료가 빠지고 필기 점수가 오른다 → 남은 완료 가능 의뢰가 있으면 다시 고른다.
- **두 의뢰가 같은 재료를 요구할 때**: 고르는 순간마다 완료 가능 여부를 다시 계산한다. 그래서 하나를 내면 다른 하나가 "완료 가능"에서 빠질 수 있고, 플레이어가 고르는 순서로 해결한다.
- 대화 중에는 시간이 멈춘다.

### 2-6. 첫날 튜토리얼 의뢰
- 1일 밤, 크리처를 만나고 "빛"을 배운 뒤 받는 고정 의뢰다. **농작 재료 1 + 낚시 재료 1 + 채집 재료 1**이 필요하다.
- **시간이 흐르지 않는다.**
- **순서가 고정된다**: 농작으로 재료를 얻은 뒤에 낚시를 할 수 있고, 낚시를 한 뒤에 채집을 할 수 있다.
- **결과가 보장된다**: 작물은 물을 주면 바로 자라고, 낚시는 바로 입질이 와서 필요한 물고기가 잡히고, 채집 자리에는 필요한 재료가 반드시 있다.
- 크리처가 빛 마법으로 스포트라이트처럼 플레이어를 따라다니는 연출과 대사는 **이번 범위가 아니다.** 이번에는 위 세 가지(시간 정지, 순서 잠금, 결과 보장)를 켜고 끌 수 있는 **튜토리얼 모드 기능**만 만든다.

### 2-7. 필기 점수 (설정 에셋에서 조절, 기본값)
| 재료 희귀도 | 점수 |
|---|---|
| 흔함 | 2 |
| 보통 | 4 |
| 희귀 | 8 |

- 의뢰 점수 = 필요한 재료의 점수 합계다. 처음 가져온 재료라고 점수를 더 주지는 않는다.
- 점수에는 상한이 없고, 통과 기준은 시스템만 안다 (기준 값은 이번 범위 밖).
- 의뢰 보상은 **필기 점수만** 준다.

---

## 3. 재료가 나오는 규칙

### 3-1. 농작
- 작물은 심고 물을 주면 **1~2일 뒤** 자란다 (작물마다 데이터로 정함). 하루가 시작될 때 자란다.
- [마법 "자라라"는 삭제되었다. 물을 주는 것만으로 자란다.]
- 프로토타입 1의 "물을 주면 바로 자람"은 튜토리얼 모드에서만 쓴다.

### 3-2. 채집
- 서식지 4곳: 큰 나무 밑 그늘, 덤불, 바위틈, 초입 평지 (풀숲은 포획 전용이라 제외).
- 서식지마다 **채집 자리 8곳 중 4곳**이 하루 시작 때 켜진다. 켜진 자리마다 희귀도 확률로 재료를 고른다.

| 흔함 | 보통 | 희귀 |
|---|---|---|
| 60% | 30% | 10% |

- 재료를 발견하고 다가가 E로 줍는다.
- 의뢰 재료가 반드시 나온다는 보장은 **없다** (튜토리얼 모드 제외).

### 3-3. 낚시
- 낚을 때마다 희귀도를 흔함 60% / 보통 30% / 희귀 10%로 고른다.
- 희귀 물고기는 빠르게 움직여서, 주문 "느려져라"(2일 밤에 배움)가 있으면 잡기 쉬워진다. 주문 연결은 이번 범위가 아니다. 물고기 속도를 바꿀 수 있는 자리만 남긴다.

### 3-4. 포획 (보류)
- 이번에는 만들지 않는다. 재료 출처와 확률표에 나중에 추가할 수 있게만 설계한다 (참고 기본값: 65 / 30 / 5).

모든 확률, 자리 수, 성장 일수는 설정 에셋에서 조절한다.

## 4. 치트 (개발·촬영용)
개발 빌드와 에디터에서만 동작하고, 정식 빌드에서는 빠진다 (`UNITY_EDITOR || DEVELOPMENT_BUILD`). 키 배치는 설계에서 제안하고, 화면 구석에 켜고 끌 수 있는 치트 패널(또는 단축키 목록)을 둔다. 내가 **시연 영상을 찍을 때 반복 구간을 배속으로 넘기는 용도**로도 쓴다.

**시간**
- 일시 정지 / 다시 흐름
- 배속 ×1 / ×2 / ×4 / ×8 / ×16
- 특정 시각으로 이동 (19:00, 20:00, 23:00, 24:00 직전), 1시간 앞으로
- 다음 날로 넘기기, 특정 날짜로 이동
- 다음 날 시작 시각 변경 테스트 (예: +60분, −30분)

**의뢰**
- 게시판 새로 뽑기, 특정 의뢰를 게시판에 올리기
- 선택한 의뢰의 재료를 인벤토리에 넣기 (바로 완료 가능 상태 만들기)
- 진행 중인 의뢰 모두 비우기
- 튜토리얼 모드 켜기/끄기

**재료·점수**
- 아이템 ID로 아이템 넣기
- 채집 자리 다시 뽑기, 켜진 자리와 희귀도를 화면에 표시
- 다음 낚시를 특정 희귀도로 고정
- 작물 모두 다 자라게 하기
- 필기 점수 설정·초기화

**디버그 표시** (켜고 끔)
- 날짜, 게임 시각(분 단위), 시간대, 배속, 멈춤 원인 목록
- 게시판 의뢰 3개와 진행 중인 의뢰 상태

## 5. 폴더와 어셈블리
프로토타입 1의 구조와 의존 방향(`UI → Core`, `Gameplay → Core`)을 그대로 쓴다. 하위 폴더 예:
```
Assets/_Project/
├─ Scripts/Core/Quest/       의뢰 데이터 해석, 게시판 뽑기, 진행·전달·포기 규칙 (일반 C#)
├─ Scripts/Core/Time/        게임 시계, 하루 흐름, 멈춤 원인 관리 (일반 C#)
├─ Scripts/Core/Spawning/    채집 자리 선택, 희귀도 확률 (일반 C#)
├─ Scripts/Gameplay/...      Unity와 연결하는 얇은 컴포넌트 (게시판, 크리처 전달, 채집 자리 등)
├─ Scripts/Debug/            치트와 디버그 표시 (Runtime 어셈블리가 참조하지 않게)
├─ Tests/                    시계·의뢰·확률 단위 테스트
└─ Data/Quest/, Data/Time/   의뢰, 아이템 희귀도, 시간·확률 설정 에셋
```
- 새 어셈블리(예: Debug)가 필요하면 이유와 함께 제안하고 승인을 받는다.
- 시계와 의뢰 상태는 나중에 **D-N 날짜별 세이브**를 붙일 수 있도록 저장 가능한 데이터 형태로 분리해 둔다 (세이브 자체는 이번 범위가 아니다).

## 6. 완료 기준 (테스트 시나리오)
1. 2일 방과 후 16:00에 시작해서 시간이 흐르고, 19:00 경고 → 20:00 밤 전환 → 23:00 경고 → 24:00 경비원 처리 → 3일 방과 후가 17:00에 시작한다.
2. 책·가방·게시판 패널·크리처 대화 중에는 시간이 멈추고, 닫으면 다시 흐른다. 두 개를 겹쳐 열었다 닫아도 꼬이지 않는다.
3. 하루 시작 때 게시판이 3개(쉬움·보통·어려움, 어려움은 2일부터)로 바뀌고, 받지 않은 의뢰는 사라진다.
4. 의뢰를 3개 받으면 네 번째는 거절되고 이유가 나온다. 수락하면 필요한 씨앗이 들어온다.
5. 재료가 겹치는 두 의뢰를 모두 완료 가능하게 만든 뒤 크리처에게 하나를 전달하면, 다른 하나가 재료 부족으로 완료 가능 목록에서 빠진다.
6. 포기 메서드를 호출하면 칸이 비고, 확인 창이 뜬다 (확인 창은 임시 UI라도 됨).
7. 채집 자리 확률과 낚시 희귀도가 설정 값대로 나오는지 단위 테스트(많이 뽑아 비율 확인)가 통과한다.
8. 튜토리얼 모드에서 시간이 멈추고, 농작 → 낚시 → 채집 순서가 잠기며, 필요한 재료가 반드시 나온다.
9. 치트로 배속, 시각 이동, 날짜 이동, 재료 넣기가 동작한다. 정식 빌드 설정에서는 치트 코드가 빠진다.
10. 콘솔에 에러가 없다.

## 7. 이번에 만들지 않는 것
장르 이벤트 본편, 1·7·8일 스토리와 연출, 크리처 스포트라이트 연출, 과외(실기 점수), 시험과 엔딩, 포획, 세이브, 책 메뉴의 의뢰 상세 페이지 UI, 시간대 룰렛 UI의 최종 아트(알림 구독 연결까지만).

## 8. 진행 순서
1. 프로젝트와 프로토타입 1 코드, DESIGN.md를 읽고 현재 구조를 요약한다 (읽기만 함).
2. `Docs/DESIGN_QUEST_TIMER.md` 설계를 작성하고 설명한다. **"제작 시작"까지 기다린다.**
