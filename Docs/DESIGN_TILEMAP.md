# 설계 — 타일 에디터 테스트 씬 (텃밭·낚시 맵 바닥)

> 작성: 2026-11-05 · 브랜치 `feature/tool-tile-editor` · 지침: `Docs/HANDOFF_MAP_TILES.md`
> 상태: **설계안 — 사용자 "제작 시작" 승인 전.** 아래 내용 중 씬·스크립트·에셋은 아직 하나도 만들지 않았다.

## 0. 한 줄 요약
> **2026-11-05 사용자 정리**: 이 씬은 일회용 테스트 씬이 아니라 **타일 맵 에디터 씬**이다. 여기서 타일을 편하게 이어 칠하고 구워서, 나중에 다른 게임 플레이 씬에 실제 땅으로 가져다 쓴다. → 씬 `Scenes/Tools/TileMapEditor.unity`, 굽기 결과는 다른 씬에 놓을 수 있는 **프리팹**으로 낸다 (7장).

Tilemap은 **칠하기 전용**(에디터에서만 보임), 게임에서 보이는 바닥은 **굽기 도구가 만든 평면 메시 + 아틀라스(URP Lit)**.
타일 한 칸 크기는 **설정값 하나(`TileMapConfig.CellSize`)**로, 바꾸면 10×10 샘플 구역(칠한 칸·구운 바닥)이 그 자리에서 바로 커지고 작아진다.
경계는 **Rule Tile이 자동으로** 붙인다 → 사용자는 흙·길·짚 영역만 칠하면 된다.

### 1-3. 경계 타일 이름의 뜻 (그림 확인, 3세트 모두 같은 규칙)
**접미사 = 흙(풀이 아닌 쪽, 세트 이름의 `to_` 뒤 재료)이 있는 방향.** 나머지가 풀.

| 이름 | 그림 | 풀 위치 |
|---|---|---|
| `n` / `s` / `e` / `w` | 흙이 북 / 남 / 동 / 서쪽 절반 | 반대쪽 절반 |
| `ne` `nw` `se` `sw` (바깥 모서리) | 흙이 그 방향 **한 귀퉁이**만 | 나머지 L자 |
| `ine` `inw` `ise` `isw` (안쪽 모서리) | 흙이 두 변(예: `ine` = 북·동)을 L자로 | **반대 귀퉁이**만 (예: `ine` → 남서) |

- 위쪽 = 북(+Z)으로 본다. 경계선은 칸 가운데쯤을 지난다 (반 칸 경계)
- 확대 비교 그림: 작업용 임시 파일이라 프로젝트에 넣지 않음

### 2-2. 스크립트 (어셈블리 · 역할)
| 어셈블리 | 클래스 | 역할 |
|---|---|---|
| Core | `TileMapConfig` (ScriptableObject) | 칸 크기(m), 샘플 크기(10), 조각 크기(16), 아틀라스 여백(px), 타일 픽셀(32), 채우기 상한. 값이 바뀌면 `Changed` 이벤트 |
| Core | `TileGridMath` (일반 C#) | 칸 ↔ 로컬 좌표, 조각 나누기, 위치 기반 해시 (순수 계산, 테스트 가능) |
| Core | `TileAtlasLayout` (일반 C#) | 타일 N개 → 아틀라스 크기·칸별 UV (여백 포함) |
| Gameplay | `TileGridScaler` ([ExecuteAlways]) | Grid에 붙어 설정의 칸 크기를 Grid 배율로 바로 반영 (에디터·플레이 모두) |
| Gameplay | `PaintOnlyTilemap` | 플레이 시작 때 TilemapRenderer를 끈다 (칠하기 전용) |
| Editor | `TileFloorBaker` | 칠한 Tilemap → 조각 메시 + 아틀라스 + 머티리얼 |
| Editor | `FarmTileSetBuilder` | farm 임포트 설정, Tile·Rule Tile·팔레트 만들기 (없을 때만 만들고, 있으면 묻기) |
| Editor | `TileMapEditorSceneBuilder` | 에디터 씬 만들기 (씬이 이미 있으면 덮어쓰기 전에 확인 창) — 만듦 |
| Editor | `TileMapEditorWindow` | 작은 도구 창: 굽기 · 보기 전환(칠하기/구운 바닥) · 칸 크기 후보 · 해 각도 · 확인 1~4 버튼 |

- 실제 도구라 Sandbox가 아니라 `VoxelMagic.Editor`(Scripts/Editor/Tiles)에 둔다

- 의존 방향: Gameplay → Core, Editor → Core/Gameplay. Core는 아무것도 참조하지 않음 (지금 규칙 그대로)
- 굽기는 `Tilemap.GetSprite(칸)`으로 **Rule Tile이 이미 고른 그림**을 읽는다 → Editor 어셈블리가 Extras 패키지를 참조할 필요가 없다 (Rule Tile 에셋을 만드는 `FarmTileSetBuilder`만 참조)
- 상속·다형성: 이번 범위는 도구라 상호작용 대상이 없다. 나중에 "걸을 수 없는 칸" 같은 칸 정보가 생기면 그때 인터페이스로 묶는다 (지금은 만들지 않음)

## 3. 테스트 씬 구성
```
TileMapEditor                       (2026-11-05 만듦. [다음] = 굽기 단계에서 추가)
├─ Directional Light  농장과 같은 값: 회전 (50, 330, 0), 색 (1, 0.957, 0.839), Soft, Depth Bias 0.1 · Normal Bias 0
├─ SampleCenter       샘플 가운데 기준점 (TileGridScaler가 옮김, 배율 1 그대로)
│  ├─ Main Camera     농장과 같은 각도 (PlayerConfig Pitch 45 · Yaw 45 · 거리 8)
│  ├─ Chibi           농장 치비 모델 Student_Chibi_v2 (배율 1, Idle)
│  └─ RefCube_1m      1 m 상자 (가운데에서 동쪽 1.5 m)
├─ SampleEast         샘플 동쪽 끝 기준점
│  └─ Pond            Pond_Bank + Pond_Water (배율 2, 2, 1.5 · 회전 X 270, 농장과 같은 머티리얼·오프셋), 동쪽 끝에서 4.5 m
└─ FloorGrid          Grid(회전 X 90) + TileGridScaler   ← 칸 크기 설정이 여기 배율로 들어감
   ├─ Paint           Tilemap + TilemapRenderer   (칠하는 층 하나: 풀은 일반 Tile, 흙·길·짚은 Rule Tile)
   ├─ [다음] LitTest  Tilemap (확인 2번 전용, 평소 꺼 둠)
   └─ [다음] BakedFloor 굽기 결과
```
- 칠하는 층은 **하나**로 충분하다: 경계 그림이 풀까지 함께 그려진 불투명 그림이라 풀 층을 따로 깔 필요가 없다
- 도트 렌더링(`PixelRenderView`) 토글은 아직 넣지 않았다 (UI가 필요해 굽기 단계 도구 창과 함께 제안)
- **10 × 10칸 샘플 구역**을 미리 칠해 둔다: 바탕 meadow_grass, 그 위에 dark_garden_soil 4×4 덩어리, muddy_farm_path 한 줄(폭 2), straw ㄱ자 모양, 그리고 4-3 한계를 보여 줄 **1칸 폭 줄**과 **대각선만 닿는 칸** 하나씩
- Grid 원점은 샘플 구역 가운데가 월드 원점에 오게 놓는다 → 칸 크기를 바꾸면 가운데를 기준으로 커지고 작아짐. 치비는 가운데, 연못·상자는 옆 (사용자가 자유롭게 옮겨도 됨)
- 치비는 농장과 같은 모델: `PlayerConfig`의 아바타(`Student_Chibi_v2`, CHANGELOG 2026-11-04 기준)를 배율 1로 놓는다. 농장 씬 `Player`는 프리팹이 아니므로 씬에서 복사하지 않고, 농장 씬 자체는 건드리지 않음

## 4. 4-2 반영 — 타일 크기를 설정값으로 바로 조절
- `TileMapConfig.CellSize` (m, 시작값 **1.0**, 범위 0.25~4) 하나만 바꾸면 된다
- `TileGridScaler`가 `FloorGrid`의 **Transform 배율을 (CellSize, CellSize, CellSize)**로 둔다. Grid 자체 칸 크기는 1, 타일 그림은 PPU 32 = 1칸
  - 칠한 칸, Tilemap 그림, 구운 바닥(Grid 아래 자식이라 함께 늘어남)이 **다시 굽지 않아도** 같이 맞춰진다
  - 설정 에셋의 값을 바꾸면 `OnValidate` → `Changed` 이벤트 → 씬에 바로 반영 (씬 다시 만들기 불필요)
- 참고 후보 (도구 창에 버튼으로 빠르게 바꾸기): **A 2.133 m** (텍셀 = 치비 1복셀) · **B 1.067 m** (16복셀) · **1.0 m** (지금 텃밭 칸) · **C**는 그림을 16 px로 줄이는 방식이라 버튼 대신 굽기 옵션 "아틀라스 반 해상도"로 제공
- 도트 렌더링(`PixelRenderView`)을 같은 씬에서 켜고 끌 수 있게 해 밀도 차이를 비교 (도구 창 토글, 플레이 모드)
- 크기를 정한 뒤 `FarmConfig.CellSize`와 맞추는 일은 **이번 범위 밖** (사용자 확정 후 별도로)

- 기존 .meta를 **수정**하는 일이다 (지우지는 않음, GUID 유지)

## 6. 4-4 반영 — Rule Tile 자동 경계와 채우기

### 6-1. Rule Tile 3개 (`RT_dark_garden_soil`, `RT_muddy_farm_path`, `RT_straw_covered_ground`)
사용자는 **바탕을 meadow_grass로 깔고, 흙(길·짚) Rule Tile로 영역만 칠한다.** 테두리는 저절로 붙는다.
규칙은 "이웃이 같은 Rule Tile이면 ✔, 아니면 ✘"(8방향). 1-3의 이름 뜻에서 나온 대응:

| 칸의 이웃 상태 (✘ = 흙이 아님) | 고를 그림 |
|---|---|
| 4방향·대각선 모두 ✔ | 가운데 = `floors/<흙>` (기본 그림) |
| 북 ✘ (남·동·서 ✔) | `_s` |
| 남 ✘ | `_n` |
| 동 ✘ | `_w` |
| 서 ✘ | `_e` |
| 북·서 ✘ (구역 왼쪽 위 모서리) | `_se` |
| 북·동 ✘ | `_sw` |
| 남·서 ✘ | `_ne` |
| 남·동 ✘ | `_nw` |
| 4방향 ✔, 북동만 ✘ (안쪽 꺾임) | `_isw` |
| 4방향 ✔, 북서만 ✘ | `_ise` |
| 4방향 ✔, 남동만 ✘ | `_inw` |
| 4방향 ✔, 남서만 ✘ | `_ine` |
| 그 밖 (1칸 폭, 마주 보는 두 변 ✘ 등) | 맞는 그림 없음 → 가운데 그림 (경계가 끊겨 보임, 4-3 한계) |

- 경계가 반 칸이라 **칠한 흙 영역의 테두리 칸은 반쯤 풀로 보인다** (2026-11-05 미리보기로 확인함). 예: 6×6 텃밭 칸을 모두 흙으로 보이게 하려면 한 바퀴 더 넓게 8×8을 칠해야 한다
- 흙끼리(흙 ↔ 길) 맞닿으면 서로 "✘"라 사이에 풀 테두리가 생긴다 (그림 세트가 "풀 → X"뿐, 4-3)
- 같은 종류의 변형 섞기: 지금 farm 팩에는 변형 그림이 없다. 나중에 생기면 Rule Tile의 **Random 출력**(위치로 정해지는 값이라 다시 구워도 같음)을 쓰고, 굽기는 고른 그림을 그대로 읽는다

### 6-2. 팔레트 `Farm`
- 1줄: 바닥 12개 (meadow_grass를 맨 앞) · 2줄: Rule Tile 3개 · 한 줄 띄고 아래 3줄: 경계 세트 3개를 그림 모양대로 5×3 블록씩 (`nw n ne inw ine / w 가운데 e isw ise / sw s se`, 자동이 안 맞는 곳을 손으로 고칠 때) — 2026-11-05 만듦
- 넓은 영역: Tile Palette의 **사각형 채우기(U)**, **채우기(G)**

### 6-3. "테두리 먼저 → 안쪽 채우기"
1. 기본은 6-1 방식이라 테두리를 손으로 칠할 일이 없다
2. 손으로 테두리를 친 경우: **Flood Fill(G)**로 닫힌 안쪽을 클릭 → 같은 타일(또는 빈칸)로 이어진 곳만 채워질 것으로 **예상**. 테스트 씬에서 실제로 확인한다
3. 위 둘로 부족할 때만 도구 버튼 "경계 안 채우기"를 추가 제안: 클릭한 칸에서 경계 낱장에 막힐 때까지 퍼지고, 채울 바닥은 세트 이름(`..._to_dark_garden_soil` → `dark_garden_soil`)에서 고르며, 칸 수 상한(설정값, 시작 400칸)을 넘으면 멈추고 알림. **이번 승인 범위에는 넣지 않는다** (확인 결과를 보고 따로 묻기)

## 7. 4-1 반영 — 굽기 방식
```
[Paint Tilemap] ──GetSprite(칸)──▶ 사용한 그림 목록 ──▶ 아틀라스 PNG (Point·무압축·밉 없음, 칸마다 여백 + 가장자리 늘이기)
        │                                                      │
        └──칸 위치──▶ 16×16칸 조각마다 위를 향한 평면 메시 (칸당 사각형 1개, 법선 +Y, UV = 아틀라스 칸) ──▶ URP Lit(불투명) 머티리얼
```
- 순서: Tilemap 범위 압축 → 칸마다 그림 읽기 → 그림 PNG를 파일에서 직접 읽어(텍스처 Read/Write 설정을 바꾸지 않음) 아틀라스 합치기 → 조각 메시 저장 → `BakedFloor` 아래 조각 오브젝트 교체
- 다시 칠한 뒤 "굽기"를 누를 때 결과 폴더에 이전 결과가 있으면 **확인 창으로 먼저 묻고**, "덮어쓰기"를 고를 때만 같은 이름으로 덮어쓴다 (사용자 결정 2026-11-05). "취소"면 아무것도 바꾸지 않는다
- 그림의 회전·뒤집기(Rule Tile 회전 규칙)는 이번 규칙에 쓰지 않는다. 회전된 칸이 나오면 경고만 남긴다
- 조각 렌더러: 그림자 받기 켬, 그림자 드리우기 끔 (평면 바닥)
- 게임 중: `PaintOnlyTilemap`이 Tilemap 렌더러를 끄고 구운 바닥만 보인다. 에디터에서는 도구 창의 "보기: 칠하기 / 구운 바닥"으로 전환 (두 층이 겹쳐 깜빡이는 것 방지)
- **다른 씬에서 쓰기**: 굽기 결과를 `Art/Map/Baked/<맵 이름>/<맵 이름>_Floor.prefab`(조각 메시 + 머티리얼, 칸 크기 배율 포함)로 낸다. 게임 플레이 씬에는 이 프리팹만 놓는다 (Tilemap·Grid·에디터 스크립트 불필요). 맵 이름은 에디터 씬에서 정한다
- 칸 정보(어느 칸에 무슨 타일)는 Tilemap에 그대로 남아 나중에 걸을 수 없는 칸·충돌에 재사용 가능 (이번 범위 밖)

## 8. 확인 1~4 (테스트 씬에서 짧게)
| 번호 | 확인할 것 | 방법 | 예상 |

| 1 | XZ 바닥 방향으로 칠하기 | Grid를 X축 90° 돌린 방식으로 칠해 보고, 칸 (0,0)·(9,9)의 월드 위치와 "팔레트 위쪽 = +Z(북)"인지 확인. 안 되면 Cell Swizzle `XZY` + Tilemap Orientation `XZ`로 바꿔 비교 | X 90° 회전은 될 것 (추측) |

## 11. 여러 맵 · 선택한 맵 굽기 · 다시 불러오기 · 바닥 종류 (2026-11-06 승인·제작 완료, 11-9의 1~5단계 모두 — CHANGELOG 2026-11-06)
> 사용자 요청 (2026-11-05): 에디터 씬 안에서 새 맵을 깔 수 있게, 이전 맵도 씬에 남게, 선택한 오브젝트의 맵만 굽기, 이전 맵은 숨기거나 Transform으로 옆으로 치우기, 구워 둔 맵을 골라 다시 불러와 수정.

### 11-1. 맵 하나 = 루트 오브젝트 하나
지금은 `FloorGrid`(Grid가 X 90° 돌고 배율까지 받음) 아래 `Paint`가 있고 구운 바닥은 씬 루트에 따로 있다. 그래서 맵을 옮기거나 숨길 때 구운 바닥이 따로 논다. → **맵마다 돌리지도 키우지도 않는 루트**를 두고 그 아래에 모은다.
```
TileMapEditor
├─ Directional Light
├─ Compare                       비교용 (Main Camera · Chibi · RefCube_1m · Pond) — 선택한 맵을 따라감 (11-4)
└─ Maps
   ├─ Map_FarmSample             TileMapDocument + TileGridScaler   ← 이 오브젝트를 옮기면 맵 전체가 옮겨지고, 끄면 숨겨짐
   │  ├─ Grid                    Grid (X 90°, 배율 = 칸 크기)
   │  │  └─ Paint                Tilemap + PaintOnlyTilemap
   │  └─ FarmSample_Floor        구운 프리팹 인스턴스 (배율 = 칸 크기)
   └─ Map_<새 맵>
```
- `TileMapDocument` (맵 루트): 맵 이름, Grid·Paint·구운 바닥 참조, 구운 칸 크기, 칸 데이터 파일 참조. 플레이 중 구운 바닥 켜기는 지금처럼
- `TileGridScaler` (맵 루트로 옮김): 설정의 칸 크기를 자기 맵의 `Grid`와 구운 바닥 배율에 반영. 위치는 건드리지 않는다 (사용자가 루트를 자유롭게 옮김)
- 칸 크기 설정(`TileMapConfig`)은 지금처럼 모든 맵 공용

### 11-2. 도구 창 = "선택한 맵" 기준
- Hierarchy에서 맵 루트나 그 자식(Grid, Paint, 구운 바닥 조각 등)을 고르면 그 맵이 **작업 대상**. 창 맨 위에 "작업 대상: FarmSample" 표시
- 아무것도 안 골랐거나 맵 밖을 고르면: 맵 목록에서 고르라고 안내
- **맵 목록** (씬의 모든 맵): 줄마다 `이름 · 칸 범위 · 구움 여부 · [선택] [보이기 ✓]`. 보이기를 끄면 맵 루트를 꺼서 숨김. 옆으로 치우기는 루트 Transform을 직접 옮긴다 (목록에 "다른 맵 모두 숨기기" 버튼 하나 추가)
- 작업 대상에만 적용: 칠하기 시작(Tile Palette 대상 = 그 맵의 Paint), 굽기, 보기 전환(칠하기/구운 바닥), 맵 이름 바꾸기
- 칠하기 중 다른 맵을 고르면 Tile Palette 대상도 그 맵의 Paint로 바뀐다

### 11-3. 새 맵
- 도구 창 "새 맵": 이름, 가로 × 세로 칸(기본 **40 × 40**), 바탕 타일(기본 `meadow_grass`, 비워 두면 빈 맵), "다른 맵 숨기기"(기본 켬)
- 위치: 기존 맵들 오른쪽(+X)에 겹치지 않게 칸 4개 띄워 놓는다 → 숨기지 않아도 겹치지 않음
- 이름 규칙: 파일 이름으로 쓸 수 있어야 하고, **씬의 다른 맵이나 `Art/Map/Baked/`의 기존 폴더와 같으면 만들지 않고 알린다** (덮어쓰기 사고 방지)
- 만든 뒤 바로 그 맵을 선택하고 칠하기 상태로. Ctrl+Z로 만들기 취소 가능

### 11-4. 비교 오브젝트
- `Compare` 하나를 **작업 대상 맵의 가운데**(카메라·치비·상자)와 **동쪽 끝**(연못)으로 옮긴다 — 맵을 바꿔 고를 때마다 자동
- 맵 가운데 = 칠한 칸 범위의 가운데 (빈 맵이면 새 맵 크기 기준)

### 11-5. 굽기 + 칸 데이터 저장
- 지금 굽기에 더해 **`<맵>_Cells.asset`**(칸 데이터)을 같은 폴더에 저장: 칸 위치 목록 + 그 칸에 칠한 타일(Rule Tile이면 Rule Tile 자체, 결과 그림이 아님) + 구운 칸 크기
- 데이터 형식: `TileMapCells` (ScriptableObject, Core — `TileBase`는 Unity 기본 모듈이라 Core 의존 규칙 그대로)
- 덮어쓰기 확인 창은 지금처럼 (칸 데이터도 덮어쓴다고 문구에 추가)
- 구운 바닥 인스턴스는 그 맵 루트 아래에 놓는다

### 11-6. 구운 맵 다시 불러오기
- 도구 창 "구운 맵 불러오기": `Art/Map/Baked/` 아래 **칸 데이터가 있는 맵 목록**에서 고르거나, Project 창에서 고른 `<맵>_Floor.prefab`·`<맵>_Cells.asset`로 불러오기
- 하는 일: 새 맵 루트를 만들고(11-3 위치 규칙) 칸 데이터대로 Paint를 칠하고, 구운 프리팹 인스턴스를 연결 → 바로 수정하고 다시 굽기 가능 (같은 이름이라 굽기 때 덮어쓰기 확인)
- 같은 이름의 맵이 이미 씬에 있으면 새로 만들지 않고 그 맵을 선택한다
- 칸 데이터가 없는 예전 결과(지금 `FarmSample`)는 불러올 수 없다고 알린다 → `FarmSample`은 씬에 칠한 칸이 남아 있으니 한 번 다시 구우면 데이터가 생긴다

### 11-7. 지금 씬 옮기기 (한 번만)

### 11-10. 바닥 종류 정보 (발밑 파티클 등 확장용, 사용자 요청 2026-11-06)
나중에 "흙 위를 달리면 흙 파티클, 풀 위면 풀 파티클"을 하려면 **플레이 중에 발밑 칸의 바닥 종류를 빠르게** 알아야 한다. 지금 구운 결과(메시·그림)에는 그 정보가 없다 → 굽기 때 **칸마다 바닥 종류 번호**를 함께 굽는다.

**타일 순서 번호가 아니라 "바닥 종류"로 묶는 이유**: 풀 타일은 `meadow_grass`·`farm_grass`·`flower_meadow`처럼 여러 장이지만 파티클은 같다. 칸마다 "타일"을 저장하면 쓰는 쪽이 타일 수만큼 분기해야 한다 → 칸에는 **종류**(풀·흙·…)만 저장하고, 타일 → 종류 대응은 표 하나로 관리한다.

| 데이터 (ScriptableObject) | 어셈블리 | 내용 |
|---|---|---|
| `GroundSurface` | Core | 바닥 종류 하나: 이름(풀, 흙, 진흙, 짚, 돌, 나무판…). 나중에 발밑 파티클·발소리 등을 여기에 추가 (지금은 비워 둠) |
| `GroundSurfaceTable` | Core | 타일 → 바닥 종류 표. 에디터 씬에서만 씀 (굽기 때 읽음) |
| `GroundSurfaceMap` (굽기 결과 `<맵>_Surfaces.asset`) | Core | 칸 범위(시작 칸, 가로, 세로) + **칸마다 종류 번호 1바이트** + 번호 → `GroundSurface` 목록. 40×40 맵이면 1,600바이트 |

- **표 기본값** (farm, 표 에셋은 만들 때 이름으로 채우고 사용자가 고칠 수 있게):
  풀 = meadow_grass · farm_grass · flower_meadow / 흙 = dark_garden_soil · tilled_soil_rows · dry_dirt_path / 진흙 = muddy_farm_path / 짚 = straw_covered_ground · hay_floor / 돌 = barnyard_stones · stepping_stone_path / 나무판 = barn_floor_planks
  - Rule Tile은 칠한 재료의 종류 (`RT_dark_garden_soil` → 흙), 경계 낱장은 세트 이름의 `to_` 뒤 재료 (`..._to_dark_garden_soil_n` → 흙)
  - 표에 없는 타일을 칠했으면 굽기 때 경고 + "없음"(번호 0)
- **경계 칸**: 경계 칸은 그림상 반은 풀이지만 v1에서는 **칠한 재료**(흙)로 친다. 칸 안 위치까지 따지는 정밀판(경계 칸에 "풀 쪽 방향"을 함께 저장)은 필요해지면 추가 (추측: 파티클 정도면 v1로 충분)
- **플레이 중 찾기**: 구운 프리팹 루트에 `GroundSurfaceSource`(Gameplay)를 붙여 `<맵>_Surfaces.asset`을 참조
  - `TryGetSurface(월드 위치, out 바닥 종류)`: (위치 − 프리팹 위치) ÷ 칸 크기 → 칸 → 배열 한 칸 읽기. 계산 몇 번 + 배열 읽기 1번이라 매 걸음 불러도 가벼움
  - 프리팹을 게임 씬 어디에 옮겨 놓아도 프리팹 위치·배율 기준으로 계산하므로 맞다 (프리팹 회전은 하지 않는다는 전제)
  - 씬에 바닥 프리팹이 여러 개일 수 있으니 켜질 때 목록에 등록 → 쓰는 쪽은 `GroundSurfaceQuery.TryGet(위치, out 종류)` 하나만 부르면 됨 (물리·충돌체 불필요)
- **이번 범위**: 데이터·굽기·찾기 기능까지 + 에디터 씬 플레이 모드에서 치비 발밑 종류를 화면 구석에 표시해 확인. **실제 파티클·플레이어 연결은 범위 밖** (나중에 `GroundSurface`에 파티클을 넣고 플레이어 걸음에서 `GroundSurfaceQuery`를 부르면 됨)
- 칸 데이터(11-5, 에디터용: 정확한 타일 → 다시 불러오기)와 바닥 종류 맵(게임용: 가벼운 번호)은 **따로 둔다**. 게임 씬이 Rule Tile·타일 에셋을 참조하지 않게 하려는 것

### 11-11. 구운 상태로 되돌리기 (사용자 요청·승인 2026-11-06)
- 구운 뒤 잘못 칠했을 때, 작업 대상 맵의 칠한 칸을 **마지막으로 구운 칸 데이터(`<맵>_Cells.asset`)로 그 자리에서** 바꾼다 (맵 위치·구운 바닥 연결은 그대로)
- 도구 창 굽기 영역의 **"구운 상태로 되돌리기"**: 확인 창으로 묻고 실행, Ctrl+Z로 취소 가능. 칸 데이터가 없으면(구운 적 없음, 옛 굽기) 버튼이 꺼지고 이유를 보인다
- 굽기 결과 파일은 건드리지 않는다 (읽기만)

### 11-9. 제작 순서 (기능마다 확인 → 보고 → 사용자 확인)
1. 구조 바꾸기(11-1·11-7) + 맵 루트 옮기기/숨기기에 구운 바닥이 따라가는지
2. 도구 창 선택 기준·맵 목록·새 맵 (11-2~11-4)
3. 칸 데이터 저장 + 다시 불러오기 (11-5·11-6)
4. 바닥 종류: 표·굽기·`GroundSurfaceQuery` + 발밑 종류 표시로 확인 (11-10)
5. `TILEMAP_EDITOR_GUIDE.md`를 단계별 조작법으로 다시 쓰기
